| 层次 | 状态 | 证据 |

## 二、本轮做了什么

### 2.1 重打包（关键前置）

原 `release/` 产物生成于 2026-10-21，**早于 M7（MCP）代码**，用它验收等于验收旧版本。本轮先重打：

```
pnpm dist   # → release/win-unpacked + AI-IDE-0.1.0-win-x64.exe
pnpm verify:package
```

结果：`packaging win32 x64 electron=44.9.0` → `building target=nsis` → `verify:package` 11 项全 PASS（内核 19083264 bytes 与 `target/release` 一致、asar 内无 `*.exe`、asar 内 `main` 指向 `out/main/index.js`、无 `node_modules` 残留、安装包存在）。

> 踩坑记录：直接 `pnpm dist` 会在 `packaging` 阶段 `connect ETIMEDOUT 20.205.243.166:443`（electron 二进制走 GitHub 下载被墙）失败。解法是设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 再打，见 §五 第 1 条。

### 2.2 新增 `scripts/e2e-m8.mjs`（13 项断言）

设计要点——与 `e2e-m1.mjs`（`electron .` 拉开发树）互补，本脚本**拉打包产物**并把用户目录整体搬到仓库内临时目录：

| 手段 | 做法 | 它证明了什么 |
|---|---|---|
| 拉打包态 | `electron.launch({ executablePath: release/win-unpacked/AI IDE.exe })` | 验的是用户真正会双击的那个 exe，不是开发树 |
| 干净 profile | `USERPROFILE` / `APPDATA` / `LOCALAPPDATA` / `TEMP` 全部指到 `target/e2e-m8-profile`，并清除 `AI_IDE_*` 覆盖 | 不蹭开发机既有配置，能暴露「只在开发机才跑得起来」的隐性问题 |
| 包内内核 | 断言 `resources/core/ai-ide-core.exe` 存在且非 0 字节，再由 `getCoreStatus()` 断言 `state=ready` | 内核真的在 asar 外、打包态 `resolveCoreBinary()` 分支正确 |
| 真干活 | stub 目录框 → 点「打开目录」→ 文件树 → 点 `main.ts` → 断言 Monaco `.view-lines` 含 `packaged-hello` | 打包后 IPC 链路、文件读取、编辑器全通 |
| M7 是否进包 | 点活动栏「MCP Server」→ 断言面板出现、空配置态不报错 | 防止「源码有、包里没有」的剪刀差 |
| 退出卫生 | `tasklist` 前后比对 `ai-ide-core.exe` 计数 | 不残留孤儿内核 |

## 四、已知限制

1. **未在干净 Windows 机器上跑 NSIS 安装包**：本轮验的是 `win-unpacked` 目录 + 隔离 profile，属「等价近似」而非「真安装」。安装 / 卸载 / 开始菜单快捷方式 / 首次启动 UAC 路径 / 文件关联均无自动化证据。
2. **未验运行库缺失场景**：`05` 里程碑的硬指标「无缺失运行库」只有「开发和本机运行成功」这一间接证据，未在缺 VC++ / .NET 的镜像上验过。
3. **未验签名**：安装包无代码签名，SmartScreen 会拦；未做签名链路。
4. **未验多显示器 / 缩放下首次启动**：e2e 在默认 DPI 下跑。
5. **离线打包不可用**：electron 二进制走网络下载，构建机需能访问镜像（或预置 `%LOCALAPPDATA%\electron\Cache`）。
6. **`e2e:m8` 不入 `verify:ci`**：依赖 `pnpm dist` 产物（数分钟 + 网络），只做发布前门禁。
