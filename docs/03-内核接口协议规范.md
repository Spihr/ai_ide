# AI IDE 内核接口协议规范（Core Protocol v1）

> 文档版本：v0.1（待审阅）
> 实现状态：截至 2026-10-21，`crates/protocol/src/methods.rs` 的 `IMPLEMENTED`（40 项，能力清单的唯一真相源）与 `crates/core/src/dispatch.rs` 的分支一一对应，本文方法目录中**已实现并可路由**的是：`core.hello` / `core.ping` / `core.stats` / `core.shutdown`、`$/cancelRequest`、`workspace.open` / `close` / `tree` / `read_file` / `write_file` / `create` / `rename` / `delete` / `reveal`、`search.files` / `search.content`、`provider.upsert` / `list` / `delete` / `test`、`model.upsert` / `list` / `delete`、`llm.chat_stream` / `cancel` / `list_models` / `count_tokens`、`agent.start` / `stop` / `decide`。事件侧已落地 `workspace.changed`、`provider.changed`、`llm.*`（`started` / `delta` / `reasoning` / `tool_call` / `usage` / `finished` / `error`）与 `agent.approval_required` / `agent.finished`。M3（上下文引用）**未新增任何方法**：只在既有 `llm.chat_stream` 上扩展了 `context` 入参（`ChatContext` / `ContextRef`，四类引用由内核渲染后注入对话），并让 `llm.count_tokens` 同时接受 `texts[]`。M4（Agent 闭环）新增 `agent.start` / `agent.stop` / `agent.decide` 三个方法与 `agent.approval_required` / `agent.finished` 两条事件；M5 切片二新增 `session.create` / `list` / `get` / `update` / `delete` / `append_message` / `messages` 七个方法（落盘在 `crates/store`，`crates/core/src/session_api.rs` 只做协议翻译）；M5 切片三再补 `session.export`（Markdown / JSON 写指定绝对路径，渲染在 `crates/core/src/session_export.rs`）与 `session.fork`（在 `crates/store` 的事务里复制会话与全部消息并重映射父子链）；M5 切片四新增只读的 `audit.list`（审计账本 `audit_event` 表的查询接口，写入由会话处理器旁路记录）。方法清单升至 **40 项**（已由 `crates/protocol` 单测 `IMPLEMENTED.len() == 40` 锁定）。

其余（`terminal.*` / `git.*` / `mcp.*` / `permission.*` / `search.symbols` / `workspace.indexed` / `core.log`）**尚未实现**，属设计目标；`DECLARED_NOT_IMPLEMENTED` 目前为空表，用于「协议先定义、实现后补」的过渡（M4 的 `agent.*`、M5 的 `session.*` 九个方法与 `audit.list` 已全部接线，直接进 `IMPLEMENTED`）。

## 1. 通用约定

### 1.1 帧格式

```
{"jsonrpc":"2.0","id":"1","method":"workspace.open","params":{...}}\n
{"jsonrpc":"2.0","id":"1","result":{...}}\n
{"jsonrpc":"2.0","method":"llm.token","params":{...}}\n          // 通知（无 id）
{"jsonrpc":"2.0","id":"1","error":{"code":-32602,"message":"...","data":{...}}}\n
```

### 1.2 命名规范

- 方法名：`<域>.<动作>`，域与动作均小写蛇形（`llm.chat_stream`）。
- 事件名（通知）：`<域>.<事件>`（`agent.tool_started`）。
- 所有 ID 为字符串（UUID v4），由 Main 生成。

### 1.3 错误码

| 码 | 含义 | 说明 |
|---|---|---|
| -32700 | Parse error | 非法 JSON |
| -32600 | Invalid request | 缺字段 / 未知方法 |
| -32601 | Method not found | 未实现 |
| -32602 | Invalid params | 参数 schema 校验失败 |
| -32603 | Internal error | 内核内部异常 |
| 1001 | Workspace not opened | 未打开工作区 |
| 1002 | Path out of workspace | 路径越界（安全拒绝） |
| 1003 | Path denied | 命中敏感路径规则 |
| 2001 | Provider not configured | Provider 不存在/未启用 |
| 2002 | Provider auth failed | 401/403，原文回传于 `data.upstream` |
| 2003 | Provider rate limited | 429，`data.retry_after_ms` |
| 2004 | Context overflow | 超出上下文窗口，`data.tokens` |
| 3001 | Tool not allowed | 权限策略为 deny |
| 3002 | Tool timeout | 命令执行超时 |
| 3003 | Diff apply conflict | 目标内容与预期不匹配 |
| 4001 | Cancelled | 被 `$/cancelRequest` 中断 |
| 5001 | Session not found | 会话不存在（`data.session_id`） |
| 5002 | Store unavailable | 会话库未就绪 / 未挂载 |
| 5003 | Store error | 会话库读写失败 |
| 5004 | Export failed | 导出写盘失败（`data.path`） |
| 5005 | Session too large | 消息数超过单次导出 / 分叉上限（`data.count` / `data.max`） |

### 1.4 取消

```
{"jsonrpc":"2.0","method":"$/cancelRequest","params":{"id":"<被取消请求的 id>"}}
```
被取消方返回 `{"error":{"code":4001,...}}`，并停止后续事件推送。

```jsonc
{
  "stream_id": "s-uuid",
  "session_id": "sess-uuid",
  "model_ref": { "provider_id": "p1", "model_id": "gpt-4o-mini" },
  "messages": [

    { "role": "assistant", "content": "...", "tool_calls": [{ "id":"c1","name":"read_file","arguments":"{\"path\":\"src/a.ts\"}" }] },
    { "role": "tool", "tool_call_id": "c1", "content": "..." }
  ],
  "tools": [ { "name":"read_file", "description":"...", "parameters": { /* JSON Schema */ } } ],
  "tool_choice": "auto",
  "params": { "temperature": 0.2, "max_output_tokens": 4096, "stop": [], "extra": {} },
  "context": {
    "workspace_id": "ws1",             // 留空回落到活动工作区
    "refs": [                          // 注入顺序即数组顺序
      { "kind": "file",         "path": "src/a.ts", "start_line": 10, "end_line": 40 },
      { "kind": "folder",       "path": "src" },
      { "kind": "selection",    "path": "src/a.ts", "start_line": 12, "end_line": 18 },
      { "kind": "selection",    "path": "src/a.ts", "text": "尚未落盘的选区原文" },
      { "kind": "current_file", "path": "src/b.ts", "label": "b.ts" }
    ],
    "compress": { "enabled": true, "strategy": "truncate", "budget_tokens": 8000 }
  }
}
```

**对应事件**

| 事件 | 载荷 | 说明 |
|---|---|---|
| `llm.started` | `{stream_id, model_ref, started_at}` | 请求已发出 |
| `llm.delta` | `{stream_id, text:"..."}` | 文本增量 |
| `llm.reasoning` | `{stream_id, text:"..."}` | 推理模型思考增量（若有） |
| `llm.tool_call` | `{stream_id, index, id, name, arguments_delta}` | 工具调用增量拼装 |
| `llm.usage` | `{stream_id, prompt_tokens, completion_tokens, cached_tokens?}` | 用量 |
| `llm.finished` | `{stream_id, finish_reason, message_id}` | 正常结束 |
| `llm.error` | `{stream_id, code, message, upstream?}` | 异常结束 |

**`context`：上下文引用（M3）**

`ChatContext` = `{workspace_id?, refs[], compress?}`，`ContextRef` = `{kind, path, start_line?, end_line?, text?, label?}`，`kind ∈ {file, folder, selection, current_file}`。

- **注入位置**：内核把 `refs` 按数组顺序渲染成一段文本，作为**第一条 `system` 消息**插在 `messages` 之前；`refs` 为空或缺省时**不注入**任何内容（M2 行为不变）。
- **来源标注**：`file` / `current_file` / `selection` 渲染为 `<file|current_file|selection path="…" lines="a-b">`，正文逐行前缀行号（`12| …`）；`folder` 渲染为 `<folder path="…" depth="2">` 的浅层目录树（目录名带 `/`，不做全量递归）。`label` 只用于 UI 展示，不注入对话。
- **选区口径**：`selection` 同时给了行号与 `text` 时**以行号为准**（避免两处口径打架）；只给 `text` 时按原文注入，供编辑器缓冲区尚未落盘的场景使用。
- **失效与截断是标注，不是错误**：文件不存在标 `error="not_found"`、路径指向目录标 `error="not_file"`；单文件超 256 KiB 或 2000 行标 `truncated="bytes|lines"`；以上都继续注入，让模型自己看到「引的东西没进来」。
- **越界是硬失败**：引用路径先过 `PathGuard`，命中 `../` 或工作区外的绝对路径时整个请求回 `1002`，不降级成「读不到」。
- **预算是上限，超限不静默**：注入正文的估算 token 不超过 `budget_tokens`（缺省 8000；`compress.enabled:false` 表示不裁剪）。放不下的引用按 `compress.strategy` 分流：`truncate`（缺省）按行保留**前缀**（内容被切断）；`summarize` 走**离线抽取式摘要**——保留段头（来源标注）与段尾（闭合标签），中间只留头尾若干行，并以 `<!-- 摘要：原文正文共 N 行，此处省略中间 M 行 -->` 交代，结构完整，模型不会把半截内容当成全文。被裁剪段及其后所有引用都记入省略清单，正文末尾附 `<!-- 因 token 预算不足被裁剪或省略的引用：… -->` 说明行（列不下路径清单时退成只报数量的短说明）。预算小到连抬头与说明行都容不下时，内核把预算抬到保底值并在日志记录这次抬升——**绝不静默丢弃**。`summarize` 只用本地字符串处理，不调用模型、不读密钥、不联网，因此断网或未配 Provider 时照常可用；*模型*摘要（`docs/04` §2.3 第 4 级）属后续切片。
- **计数口径**：`llm.count_tokens` 同时接受 `messages[]` 与 `texts[]`，两口径可并用、结果相加（都缺省为 0）。口径按 `model_ref.model_id` 分流：已接词表的模型族（`o200k_base`：`gpt-4o*` / `gpt-4.1*` / `gpt-4.5*` / `gpt-5*` / `o1*` / `o3*` / `o4*` / `chatgpt-4o*`；`cl100k_base`：`gpt-4` / `gpt-4-*`（非 `gpt-4o`/`gpt-4.1`/`gpt-4.5`）/ `gpt-3.5-*` / `gpt-35-*` / `text-embedding-*`）走真实分词器，回 `exact:true`，`note` 点明所用词表；其余模型回落内核估算器，回 `exact:false`。调用方**只依据 `exact` 判断该不该当精确值用**，字段含义不变。*真实*用量仍以上游在 `llm.usage` 回报的 `prompt_tokens` 为准（含厂商侧额外的消息模板开销，与本地计数允许有差）。引用预算裁剪（M3 §2.4）按估算口径，不随精确计数改变。

> 实现注记（M5 切片二）：会话 `id` 由 `crates/store` 生成（UUID v4），协议层不发 id；
> `session.list` 的 `query` 是标题子串（大小写不敏感），`total` 为过滤后总数；
> `session.update` 只回最新 `SessionView`，`title` 与 `model_ref` 至少给一个（都给则先改名再换模型），
> 空白标题按 `-32602` 拒绝。会话不存在一律 `5001`，库未就绪 / 读写失败是 `5002` / `5003`；
> 消息超过 10000 条（导出 / 分叉的硬上限）报 `5005`，写盘失败报 `5004`。
>
> 实现注记（M5 切片三）：
> - `session.export` 的 `out_path` **必须是绝对路径**（相对路径按 `-32602` 拒绝，避免文件落到内核 cwd）；
>   指向已存在的目录时，内核按「标题-会话短 id」生成文件名，缺省扩展名 `.md` / `.json`；
>   父目录不存在会自动建。`format` 缺省 `markdown`；JSON 产物是 `SessionExportDocument`
>   （`format_version` 固定 1，字段与协议 DTO 一致，客户端据此判断兼容性）。
> - `session.fork` 的 `from_message_id` 是**截断点（含）**，缺省复制全部；消息不属于源会话时报 `-32602`，
>   不会静默退化成「复制全部」。父子链在新 id 空间内重映射，父消息未被复制的则置空。
>   消息 `created_at` 原样保留，新会话标题缺省为「原标题（分支）」。
> - 两个方法都在**同一事务**内读源会话写新会话：失败不会留下半截会话。

### 2.11 审计日志 `audit.*`

| 方法 | 参数 | 返回 |
|---|---|---|
| `audit.list` | `{session_id?, kind?, since_ms?, until_ms?, limit?, offset?}` | `{events[], total}` |

> 实现注记（M5 切片四）：审计账本落在 `crates/store` 的 `audit_event` 表
> （迁移 `0002_audit_event.sql`），**append-only**：只有 `record_audit` 写入，
> 没有更新 / 删除接口——能被改写的审计等于没有审计。
>
> - **事件类型**（`model::audit_kind`）：`session.created` / `session.updated`
>   （改名或换默认模型）/ `session.deleted` / `session.exported` / `session.forked`。
>   `session.forked` 记在**新会话**上，`detail.source_session_id` 指向源会话。
> - **脱敏**：`summary` 与 `detail` 在**写库前**由 `crates/store/src/redact.rs` 脱敏
>   （键名命中 `api_key` / `token` / `secret` / `password` / `authorization` 等一律打码，
>   文本里的 `sk-…`、`Bearer …`、`api_key=…` 形态被替换为 `***`），**读取时再脱敏一次**
>   兜底老库与手工改动。协议侧返回的值已是安全值，客户端不需要也不应该再处理。
> - **不影响业务**：写审计是旁路，失败只记 `tracing::warn!`，绝不把已成功的
>   会话操作翻成错误（否则会出现「删掉了但报错」）。
> - **查询**：按 `created_at` 倒序（同刻按 `id` 倒序）分页，`total` 是过滤条件下的
>   命中总数、不受 `limit` / `offset` 影响；`limit` 缺省 50、夹到 `1..=500`；
>   `session_id` / `kind` 传空白串等同不过滤；`since_ms > until_ms` 按 `-32602` 拒绝。
> - **留存**：会话删除后审计记录仍在（表上不挂外键、不做级联），这是刻意的。

Core → Main  agent.approval_required {approval_id:"a1", tool:"edit_file", risk:"medium",
                                      reason:"将修改已存在的文件"}

Core → Main  agent.tool_finished {call_id:"c2", ok:true, summary:"应用 2 处修改", artifacts:["src/api.ts"]}
