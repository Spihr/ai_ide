> 码值为什么不是 `6001`–`6009`：`6xxx` 段并不空。终端已占 `6001`–`6004`（会话不存在 / 启动 shell 失败 / PTY IO 失败 / 参数非法），`crates/protocol/src/error.rs` 里还有一条把这段钉死的断言。插件改走 `6101`–`6109`，并在同文件加了 `plugin_error_codes_use_their_own_61xx_band` 用例，同时钉住「在 61xx 段内、互不重复、不与 6001–6099 重叠」。

其余（`workspace.indexed`，以及 Git 的写操作扩展如分支切换 / 拉取推送）**尚未实现**，属设计目标；`core.log` 已在 P5 切片九由内核侧接通（`CoreLogLayer` → 通道 → `pump` → `Peer::forward_log`），不再是缺口。`DECLARED_NOT_IMPLEMENTED` 目前为空表，用于「协议先定义、实现后补」的过渡（M4 的 `agent.*`、M5 的 `session.*` 九个方法与 `audit.list`、M6 的 `terminal.*` 与 `git.*`、M7 的 `mcp.*` 已全部接线，直接进 `IMPLEMENTED`）。

> 载体：Main ↔ Core，**JSON-RPC 2.0 / NDJSON（每行一条消息，UTF-8，`\n` 结尾）**
> 契约来源：`crates/protocol`（Rust 定义 → 生成 TS 类型）

## 1. 通用约定

### 1.1 帧格式

```
{"jsonrpc":"2.0","id":"1","method":"workspace.open","params":{...}}\n
{"jsonrpc":"2.0","id":"1","result":{...}}\n
{"jsonrpc":"2.0","method":"llm.token","params":{...}}\n          // 通知（无 id）
{"jsonrpc":"2.0","id":"1","error":{"code":-32602,"message":"...","data":{...}}}\n
```

### 1.2 命名规范

- 方法名：`<域>.<动作>`，域与动作均小写蛇形（`llm.chat_stream`）。
- 事件名（通知）：`<域>.<事件>`（`agent.tool_started`）。
- 所有 ID 为字符串（UUID v4），由 Main 生成。

### 1.3 错误码

| 码 | 含义 | 说明 |
|---|---|---|
| -32700 | Parse error | 非法 JSON |
| -32600 | Invalid request | 缺字段 / 未知方法 |
| -32601 | Method not found | 未实现 |
| -32602 | Invalid params | 参数 schema 校验失败 |
| -32603 | Internal error | 内核内部异常 |
| 1001 | Workspace not opened | 未打开工作区 |
| 1002 | Path out of workspace | 路径越界（安全拒绝） |
| 1003 | Path denied | 命中敏感路径规则 |
| 2001 | Provider not configured | Provider 不存在/未启用 |
| 2002 | Provider auth failed | 401/403，原文回传于 `data.upstream` |
| 2003 | Provider rate limited | 429，`data.retry_after_ms` |
| 2004 | Context overflow | 超出上下文窗口，`data.tokens` |
| 3001 | Tool not allowed | 权限策略为 deny |
| 3002 | Tool timeout | 命令执行超时 |
| 3003 | Diff apply conflict | 目标内容与预期不匹配 |
| 4001 | Cancelled | 被 `$/cancelRequest` 中断 |
| 5001 | Session not found | 会话不存在（`data.session_id`） |
| 5002 | Store unavailable | 会话库未就绪 / 未挂载 |
| 5003 | Store error | 会话库读写失败 |
| 5004 | Export failed | 导出写盘失败（`data.path`） |
| 5005 | Session too large | 消息数超过单次导出 / 分叉上限（`data.count` / `data.max`） |

### 1.4 取消

```
{"jsonrpc":"2.0","method":"$/cancelRequest","params":{"id":"<被取消请求的 id>"}}
```
被取消方返回 `{"error":{"code":4001,...}}`，并停止后续事件推送。

### 2.1 内核生命周期 `core.*`

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `core.hello` | `{client_version, protocol_version, platform, locale}` | `{core_version, protocol_version, capabilities[]}` | 握手，校验协议版本兼容 |
| `core.ping` | `{}` | `{pong: true, uptime_ms}` | 心跳 |
| `core.stats` | `{}` | `{rss_mb, cpu_pct, tasks_active}` | 资源自检 |
| `core.shutdown` | `{graceful: bool}` | `{ok}` | 优雅退出（刷盘后退出） |

### 2.2 工作区 `workspace.*`

| 方法 | 参数 | 返回 |
|---|---|---|
| `workspace.open` | `{path, watch?: bool}` | `{workspace_id, root, name, stats:{files,dirs,ignored}, indexing: bool}` |
| `workspace.close` | `{workspace_id}` | `{ok}` |
| `workspace.tree` | `{workspace_id, path?, depth?, include_ignored?}` | `{entries:[{name,path,kind,size,mtime,ignored}]}` |
| `workspace.read_file` | `{path, encoding?, max_bytes?}` | `{content, encoding, eol, size, truncated, hash}` |
| `workspace.write_file` | `{path, content, expected_hash?, eol?}` | `{ok, hash}` |
| `workspace.create` | `{path, kind: file\|dir}` | `{ok}` |
| `workspace.rename` | `{from, to, overwrite?}` | `{ok}` |
| `workspace.delete` | `{paths[], to_trash: true}` | `{ok, failed[]}` |
| `workspace.reveal` | `{path}` | `{ok}` |

> `write_file` 带 `expected_hash` 时做乐观锁：磁盘内容与预期不符返回 `3003`，防止覆盖用户手改。
> `write_file` 不带 `eol` 时沿用原文件换行风格；显式传 `lf` / `crlf` 则强制转换。
>
> **工作区相关事件（Core → Main，单向通知）**
>
> | 事件 | 载荷 | 触发时机 |
> |---|---|---|
> | `workspace.changed` | `{workspace_id, changes:[{path, kind: created\|modified\|deleted, old_path}]}` | `workspace.open` 时 `watch:true` 生效后，工作区内文件被外部程序改动（去抖后成批推送） |
> | `workspace.indexed` | `{workspace_id, stats:{files,dirs,ignored}}` | 后台全量（或增量）索引完成时；M1 的索引随 `workspace.open` 同步建完（返回体 `indexing:false` 并已带 `stats`），故 **M1 不推送**该事件，留给 M2 引入后台索引后启用 |
> | `core.log` | `{level, target, message}` | 内核日志转发，便于 Main 统一落盘。**已由内核主动推送**（P5 切片九）：`crates/core/src/core_log.rs` 的 `CoreLogLayer` 把 tracing 事件收成记录，经无界通道由 `pump` 逐条 `Peer::forward_log` 发帧；`level` 为小写、`message` 已过 `redact_text` 并截断至 4 KiB，`AI_IDE_CORE_LOG_PUSH=off` 可关；本模块与 `crate::peer` 自身的事件不上报（防反馈回路） |

### 2.3 搜索 `search.*`

| 方法 | 参数 | 返回 |
|---|---|---|
| `search.files` | `{workspace_id, query, glob?, limit?}` | `{matches:[{path, score}]}` |
| `search.content` | `{workspace_id, query, is_regex?, case_sensitive?, includes?, excludes?, max_results?}` | `{matches:[{path,line,column,preview}]}` |
| `search.symbols` | `{workspace_id, query, kinds?}` | `{symbols:[{name,kind,path,range}]}` |

`search.symbols` 的口径（切片一内核 + 切片二外壳入口，两端已接通）：

- `kind` 取值 `function` / `method` / `struct` / `class` / `enum` / `interface` / `trait` / `const`（`SymbolKind`，`snake_case`）；`kinds` 为入参白名单，缺省返回全部。
- `query` 对符号名做大小写不敏感的子串匹配，空串视为「列出全部符号」。
- `path` 是相对工作区根的路径（正斜杠），`range` 为 `{start_line, end_line}`，行号 1-based、闭区间，`end_line` 落在声明块的末行（单行声明时与 `start_line` 相等）。
- 抽取方式是**行首声明 + 作用域跟踪**的轻量扫描（`crates/indexer/src/symbols.rs`），不建语法树：快、零依赖、对格式容错，但嵌套声明、跨行签名、宏生成的项可能漏抽——命中的是「候选符号」，不是编译器语义上的完整符号表。
- 覆盖 Rust / TypeScript / TSX / JavaScript / Python / Go / Java；未命中或索引为空时回 `{symbols:[]}`，不报错。
- 外壳入口（切片二）：命令面板内置命令「转到符号…」（`Ctrl+T`，快捷选择器）与搜索面板的「符号」模式共用同一次检索结果；选中后打开 `path` 并把光标定位到 `range.start_line`（协议无 column，列固定为 1）。

**`llm.chat_stream` 参数**

```jsonc
{
  "stream_id": "s-uuid",
  "session_id": "sess-uuid",
  "model_ref": { "provider_id": "p1", "model_id": "gpt-4o-mini" },
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user",   "content": "...", "attachments": [{ "type":"file","path":"src/a.ts" }] },
    { "role": "assistant", "content": "...", "tool_calls": [{ "id":"c1","name":"read_file","arguments":"{\"path\":\"src/a.ts\"}" }] },
    { "role": "tool", "tool_call_id": "c1", "content": "..." }
  ],
  "tools": [ { "name":"read_file", "description":"...", "parameters": { /* JSON Schema */ } } ],
  "tool_choice": "auto",
  "params": { "temperature": 0.2, "max_output_tokens": 4096, "stop": [], "extra": {} },
  "context": {
    "workspace_id": "ws1",             // 留空回落到活动工作区
    "refs": [                          // 注入顺序即数组顺序
      { "kind": "file",         "path": "src/a.ts", "start_line": 10, "end_line": 40 },
      { "kind": "folder",       "path": "src" },
      { "kind": "selection",    "path": "src/a.ts", "start_line": 12, "end_line": 18 },
      { "kind": "selection",    "path": "src/a.ts", "text": "尚未落盘的选区原文" },
      { "kind": "current_file", "path": "src/b.ts", "label": "b.ts" }
    ],
    "compress": { "enabled": true, "strategy": "truncate", "budget_tokens": 8000 }
  }
}
```

**对应事件**

| 事件 | 载荷 | 说明 |
|---|---|---|
| `llm.started` | `{stream_id, model_ref, started_at}` | 请求已发出 |
| `llm.delta` | `{stream_id, text:"..."}` | 文本增量 |
| `llm.reasoning` | `{stream_id, text:"..."}` | 推理模型思考增量（若有） |
| `llm.tool_call` | `{stream_id, index, id, name, arguments_delta}` | 工具调用增量拼装 |
| `llm.usage` | `{stream_id, prompt_tokens, completion_tokens, cached_tokens?}` | 用量 |
| `llm.finished` | `{stream_id, finish_reason, message_id}` | 正常结束 |
| `llm.error` | `{stream_id, code, message, upstream?}` | 异常结束 |

**`context`：上下文引用（M3）**

`ChatContext` = `{workspace_id?, refs[], compress?}`，`ContextRef` = `{kind, path, start_line?, end_line?, text?, label?}`，`kind ∈ {file, folder, selection, current_file}`。

- **注入位置**：内核把 `refs` 按数组顺序渲染成一段文本，作为**第一条 `system` 消息**插在 `messages` 之前；`refs` 为空或缺省时**不注入**任何内容（M2 行为不变）。
- **来源标注**：`file` / `current_file` / `selection` 渲染为 `<file|current_file|selection path="…" lines="a-b">`，正文逐行前缀行号（`12| …`）；`folder` 渲染为 `<folder path="…" depth="2">` 的浅层目录树（目录名带 `/`，不做全量递归）。`label` 只用于 UI 展示，不注入对话。
- **选区口径**：`selection` 同时给了行号与 `text` 时**以行号为准**（避免两处口径打架）；只给 `text` 时按原文注入，供编辑器缓冲区尚未落盘的场景使用。
- **失效与截断是标注，不是错误**：文件不存在标 `error="not_found"`、路径指向目录标 `error="not_file"`；单文件超 256 KiB 或 2000 行标 `truncated="bytes|lines"`；以上都继续注入，让模型自己看到「引的东西没进来」。
- **越界是硬失败**：引用路径先过 `PathGuard`，命中 `../` 或工作区外的绝对路径时整个请求回 `1002`，不降级成「读不到」。
- **预算是上限，超限不静默**：注入正文的估算 token 不超过 `budget_tokens`（缺省 8000；`compress.enabled:false` 表示不裁剪）。放不下的引用按 `compress.strategy` 分流：`truncate`（缺省）按行保留**前缀**（内容被切断）；`summarize` 走**离线抽取式摘要**——保留段头（来源标注）与段尾（闭合标签），中间只留头尾若干行，并以 `<!-- 摘要：原文正文共 N 行，此处省略中间 M 行 -->` 交代，结构完整，模型不会把半截内容当成全文。被裁剪段及其后所有引用都记入省略清单，正文末尾附 `<!-- 因 token 预算不足被裁剪或省略的引用：… -->` 说明行（列不下路径清单时退成只报数量的短说明）。预算小到连抬头与说明行都容不下时，内核把预算抬到保底值并在日志记录这次抬升——**绝不静默丢弃**。`summarize` 只用本地字符串处理，不调用模型、不读密钥、不联网，因此断网或未配 Provider 时照常可用；*模型*摘要（`docs/04` §2.3 第 4 级）属后续切片。
- **计数口径**：`llm.count_tokens` 同时接受 `messages[]` 与 `texts[]`，两口径可并用、结果相加（都缺省为 0）。口径按 `model_ref.model_id` 分流：已接词表的模型族（`o200k_base`：`gpt-4o*` / `gpt-4.1*` / `gpt-4.5*` / `gpt-5*` / `o1*` / `o3*` / `o4*` / `chatgpt-4o*`；`cl100k_base`：`gpt-4` / `gpt-4-*`（非 `gpt-4o`/`gpt-4.1`/`gpt-4.5`）/ `gpt-3.5-*` / `gpt-35-*` / `text-embedding-*`）走真实分词器，回 `exact:true`，`note` 点明所用词表；其余模型回落内核估算器，回 `exact:false`。调用方**只依据 `exact` 判断该不该当精确值用**，字段含义不变。*真实*用量仍以上游在 `llm.usage` 回报的 `prompt_tokens` 为准（含厂商侧额外的消息模板开销，与本地计数允许有差）。引用预算裁剪（M3 §2.4）按估算口径，不随精确计数改变。

> 实现注记（M5 切片二）：会话 `id` 由 `crates/store` 生成（UUID v4），协议层不发 id；
> `session.list` 的 `query` 是标题子串（大小写不敏感），`total` 为过滤后总数；
> `session.update` 只回最新 `SessionView`，`title` 与 `model_ref` 至少给一个（都给则先改名再换模型），
> 空白标题按 `-32602` 拒绝。会话不存在一律 `5001`，库未就绪 / 读写失败是 `5002` / `5003`；
> 消息超过 10000 条（导出 / 分叉的硬上限）报 `5005`，写盘失败报 `5004`。
>
> 实现注记（M5 切片三）：
> - `session.export` 的 `out_path` **必须是绝对路径**（相对路径按 `-32602` 拒绝，避免文件落到内核 cwd）；
>   指向已存在的目录时，内核按「标题-会话短 id」生成文件名，缺省扩展名 `.md` / `.json`；
>   父目录不存在会自动建。`format` 缺省 `markdown`；JSON 产物是 `SessionExportDocument`
>   （`format_version` 固定 1，字段与协议 DTO 一致，客户端据此判断兼容性）。
> - `session.fork` 的 `from_message_id` 是**截断点（含）**，缺省复制全部；消息不属于源会话时报 `-32602`，
>   不会静默退化成「复制全部」。父子链在新 id 空间内重映射，父消息未被复制的则置空。
>   消息 `created_at` 原样保留，新会话标题缺省为「原标题（分支）」。
> - 两个方法都在**同一事务**内读源会话写新会话：失败不会留下半截会话。
>
> 实现注记（缺口第六批：尾部翻页与消息检索）：
> - `session.messages` 的 `tail: true` 把 `offset` 的语义改成「**从末尾跳过多少条**」：
>   `tail + offset=0` 是最近一屏（长对话打开时不用先拉全量），`offset=200` 是再往前一页；
>   **返回顺序仍然是正序**（最早的在前），外层提交/回放逻辑不用反向处理。
>   仓储侧走「内层倒序取页 + 外层正序」两段 SQL，并按 `created_at` + `rowid` 排序兜同毫秒。
>   缺省 `tail=false`，老客户端行为不变。`limit` 缺省 200、夹到 `1..=10000`。
> - `session.search_messages` 是**消息级**检索：`query` 对正文做子串匹配（大小写不敏感，
>   走 SQLite `instr(lower(...))` 而不是 `LIKE`，所以 `%` / `_` 按字面量算，不会被当通配符）；
>   `session_id` 缺省 `null` 表示跨会话搜，给了则只搜该会话（会话不存在是 `5001`）；
>   空 / 纯空白 `query` 按 `-32602` 拒绝，**不会**退化成「返回全部消息」。
> - 返回的 `hits[]` 是 `MessageSearchHit`：`{message_id, session_id, session_title, role, snippet, created_at_ms}`，
>   按时间倒序（最近的在前）。`snippet` 是命中处前后各约 40 个字符的片段，命中位置按**字符**而非字节计算
>   （中文正文不会切出半个字）。`total` 是匹配总数，供客户端判断是否还要翻页。
> - 会话标题由处理器按 `session_id` 去重后逐个另查，仓储只返回消息本身——命中会话数受 `limit`
>   约束很小，比 join 更省事，也不会废掉 `MESSAGE_COLUMNS` 的显式列清单。

`TerminalView`：`{id, shell, cwd?, pid?, cols, rows, created_at_ms}`。`cwd` 只是展示用字符串；
`pid` 在平台拿不到时为 `null`。

`GitStatusEntry`：`{path, original_path?, index, worktree, kind}`。`index` / `worktree` 是 git 的
两列状态字母，未变更的一侧为 `"."`；**不透出布尔量**，因为 UI 要区分「已暂存的新增（`A`）」与
「未暂存的新增（`?`）」，合成一个 `is_new` 就再也分不开。`kind ∈ {changed, renamed, unmerged,
untracked, ignored}`（`changed` 覆盖新增 / 删除 / 修改 / 类型变更）。

`GitBranch`：`{name, oid, short_oid, is_current, is_remote, upstream}`；远端分支名形如
`origin/main`，列表顺序为本地在前、远端在后，各自按名字升序。

事件：

| 事件 | 载荷 | 语义 |
|---|---|---|
| `terminal.data` | `{terminal_id, data(base64), bytes}` | 一段原始输出（PTY 字节，客户端自行解码，非 lossy 文本） |
| `terminal.exit` | `{terminal_id, code?, signal?, at_ms}` | 子进程退出；`signal` 仅 Unix 有，Windows 恒 `null` |

要点：

- **size 夹取**：`cols ∈ [2, 500]`、`rows ∈ [1, 200]`（`DEFAULT_*` 为 80×24）。客户端布局初期量到
  `0×0` 是常态，内核夹到下限而不是报错。
- **退出统一走 `terminal.exit`**：不管是 shell 自己 `exit` 还是 `terminal.kill`，都会推这条事件，
  并把会话从 `terminal.list` 摘掉；此后对该 id 的任何操作一律 `6001`（不存在的会话）。
- **会话绑定客户端**：终端输出以通知推送，需要客户端先完成 `core.hello` 握手（与其它事件同一条通道）。
- 错误码：`6001` 会话不存在、`6002` 启动 shell 失败、`6003` PTY IO 失败、`6004` 参数非法（含 base64 解不出）。
- **`git.*` 无事件**：Git 状态是工作区内容的一个视图，`workspace.changed` 已经覆盖了这个事实来源。
  再加 `git.changed` 会让外壳收到两份事实、并在两次事件之间做无谓去抖；外壳按需重发 `git.status` 即可。
- **工作区而不是仓库**：五个方法都以工作区根为作用域（`git -C <root> --relative`）。工作区只是大仓库
  的子目录时，`status` / `diff` 只报该子树内的变更，路径一律相对工作区根、正斜杠分隔；`path` 传绝对
  路径或含 `..` 的一律 `7004`，不给「借 `-C` 跳出工作区」留口子。
- **`git.diff` 的两种基准**：`staged=false`（缺省）是「工作区相对暂存区」，`staged=true` 是「暂存区相对
  HEAD」（`git diff --cached`）。未跟踪文件两侧都不会出现——它们没有基准版本，UI 应把 `kind=untracked`
  渲染成「新文件」，而不是显示空白 diff。
- **`git.diff` 的两道闸**：`context_lines` 缺省 3、上限 100（超出**夹取**而非报错，外壳要更宽的上下文
  不该被拒）；`diff` 文本上限 1 MiB，超出只切尾部并置 `truncated=true`（头部始终完整，前端能照常渲染）。
- **`git.stage` 的 `paths` 与 `all`**：都给时按 `all`（`git add -A`，含删除）；`unstage=true` 走
  `git reset`，此时 `all` 同样表示整个暂存区。返回的 `paths` 是归一化后的回显，`staged_total` 是操作后
  仍在暂存区的条目数，UI 可直接刷角标而不必再发一次 `git.status`。
- **`git.commit` 的前置条件**：`message` 去空白后为空即 `7004`（不去问 git）；暂存区为空且 `allow_empty=false`
  是 `7005`（不是 `7003`——「没什么可提交」是可预期的用户状态，不该让 UI 去解析 stderr）。`amend=true` 改写
  HEAD，`files` 为本次提交涉及的文件数。仓库未配置 `user.name` / `user.email` 时，内核按仓库本地配置补齐一个
  临时身份，避免首次提交直接失败在「请告诉我你是谁」上。
- **错误码（Git）**：`7001` 找不到 / 无法执行 git（`data.detail`）、`7002` 工作区不是 Git 仓库
  （`data.path`）、`7003` git 非零退出（`data.args` / `data.stderr` 原文 / `data.exit_code`）、`7004` 参数非法
  （路径越界、空提交信息）、`7005` 暂存区无可提交内容。工作区未打开仍是 `3001`——「没开工作区」与
  「不是仓库」是两回事。

### 2.9 MCP（P1，M7 已接线，外壳已接通）

配置文件是 `mcp.json`（默认 `<data_dir>/mcp.json`，可用环境变量 `AI_IDE_MCP_CONFIG` 覆盖；
Server 的 `env` 值支持 `${ENV}` 展开）。进程内的连接账本收敛在 `crates/core/src/mcp_manager.rs`，
协议翻译在 `crates/core/src/mcp_api.rs`，JSON-RPC 与传输细节在 `crates/mcp`。

| 方法 | 参数 | 返回 |
|---|---|---|
| `mcp.servers` | `{}` | `{servers:[{name, transport, configured, connected, state, tool_count, last_error?}]}` |
| `mcp.connect` | `{server}` | `{server, transport, protocol_version, tool_count, tools[]}` |
| `mcp.disconnect` | `{server}` | `{server, closed, removed_tools}` |
| `mcp.tools` | `{server?}` | `{tools:[{name, namespaced_name, server, description?, input_schema}]}` |
| `mcp.call` | `{server?, tool, arguments?}` | `{server, tool, namespaced_name, content[], text, is_error, structured_content?}` |

要点：

- **`servers` 是「配置里有」∪「已连上」的并集**。`configured` / `connected` / `state`
  三态分开报：`state` 取 `configured` / `connecting` / `ready` / `stale` / `closed`。
  内核**不会**因为配置里写了某个 Server 就预拉起子进程——连接必须显式 `mcp.connect`。
- **`connect` 幂等**：已 `ready` 的直接回缓存（重复握手会多起一个子进程）；`stale` / `closed`
  的先关旧连接再重连。连上了但列不出工具视为失败，按 `8002` 上报并关掉该连接。
- **`call` 的 `server` 可省略**，此时 `tool` 必须是 `mcp__<server>__<tool>` 全名；给裸名又不给
  `server` 是参数错（`8007`），内核不替调用方猜 Server。
- **错误码分段 `8001`–`8007`**：`8001` 配置里没有这个 Server（要改配置）、`8002` 连不上（起进程
  失败 / 握手失败 / 列工具失败）、`8003` 有配置但没连（提示先 `mcp.connect`）、`8004` 连上了
  但没有这个工具（拼错名或已下架）、`8005` 调用失败（连接在调用中没了）、`8006` 超时、
  `8007` 参数错。**`8003` 必须早于 `8004` 判定**：没连上时「工具不存在」是必然结论，照直报
  `8004` 会把模型引到「换工具名」的死路上。
- **工具**执行**失败不是协议失败**：Server 回报的错误正文原样放进 `text` / `content`，`is_error: true`，
  仍是成功响应——模型要能读到失败原因再换参数重试。
- **工具注入**：每个已连接 Server 的工具按 `mcp__<server>__<tool>` 注入 agent 工具注册表，随
  `agent.start` 的运行现取快照（`crates/core/src/mcp_tools.rs`），`mcp.disconnect` 后立即下架。
  这些工具与内建工具走**同一条权限闸门**：未登记的工具一律走 `Ask` 裁决，不因来源是外部
  Server 而放宽，也不另开豁免通道。
- **不新增事件**：连接态由外壳主动调 `mcp.servers` 拉取；`mcp.*` 没有推送通道。
- **外壳放行面**：`apps/desktop/src/main/policy.ts` 只放行上面五个方法，`mcp.json` 的读写
  **不对渲染进程开放**——外壳能看连接态、能连 / 断、能试跑，改配置仍需改文件。面板在
  `tools` 拿到的 `input_schema` 上折叠展示参数形态，试跑前在渲染侧先把 `arguments` 解析成
  JSON 对象，非法 JSON 不发请求（不发出去换 `8007`）。
- **断开与试跑属写语义**：断开会把该 Server 的工具从 agent 注册表下架，试跑是真让 Server
  干活；外壳对这两个动作做行内二次确认，连接与刷新不设确认。

### 2.10 插件 `plugin.*`（P1–P5 已实现）

> **状态：十一个方法全部已实现并接线**（`crates/core/src/plugin_api.rs` 做协议翻译，
> 装载与调用收敛在 `crates/plugin`）。参数畸形仍是 `-32602`——缺 `plugin_id` 这类
> 寻址键必须报参数错，否则排查会被「插件不存在」带偏。
>
> 落地沿革（旧版此节写的是「P0 协议骨架：可路由、未实现、统一回 `6101`」，那是 P0
> 当时的真实状态，P1 起逐条替换）：
>
> - **P1**：`list` / `status` / `install` / `uninstall` 换成真实现（账本 + 包目录，
>   `install` 全程 `spawn_blocking` 拷文件、**不启动任何进程**）。
> - **P2**：`load` / `unload` / `reload` 换成真实现（起子进程、stdio 帧握手、工具
>   注册/下架、崩溃巡检落账本、自动重启上限 3 次）。
> - **P3**：`call` 换成真实现——`check_call` 六步定序（`-32602` → `6101` → `6102`
>   → `6106` → 转发 `plugin/tool-invoke` → 64 KB 按字符边界截断），每次调用（含每种
>   拒绝）都落审计行。
> - **P4**：`grant` / `revoke` 换成真实现——只改本机账本里已安装插件的能力授权位，
>   能力名按清单校验（清单外 `-32602`）；撤关键能力（`fs.write` / `net.fetch` /
>   `llm.chat`）且进程在跑时连带 `unload`。
> - **P5**：新增 `command`（命令网关，命令面板入口，闸门与 `call` 同源）并把
>   `call` 的闸门扩到网络（§7.4）与模型（§7.5）两路。
>
> 六个 `plugin.*` 一律**不再**返回 `6101`；`6101` 现在的语义收窄为「插件未安装 /
> 未加载」这一件事。验收口径见 `docs/23-插件-P5-验收报告.md`。

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `plugin.list` | `{}` | `{plugins[]}` | 已安装插件与运行态，按 id 升序 |
| `plugin.status` | `{plugin_id}` | `{plugin, tools[], commands[]}` | 单插件详情（`plugin.last_error` 供面板直显） |
| `plugin.install` | `{path}` | `{plugin, replaced}` | 校验并落盘，不启动进程 |
| `plugin.uninstall` | `{plugin_id}` | `{plugin_id, removed_tools, removed_dir}` | 先卸载再删目录，删不掉如实回 `removed_dir:false` |
| `plugin.load` | `{plugin_id}` | `{plugin, tools[]}` | 授权齐备才 spawn 并握手 |
| `plugin.unload` | `{plugin_id}` | `{plugin_id, removed_tools}` | 停进程 + 工具下架 |
| `plugin.reload` | `{plugin_id}` | `{plugin, tools[]}` | 停再起 |
| `plugin.call` | `{plugin_id, method, params?}` | `{plugin_id, method, content, truncated}` | 调用网关（六道闸门） |
| `plugin.command` | `{plugin_id, command, args?}` | `{plugin_id, command, content, truncated}` | 命令网关（P5 切片二；命令来自 `status.commands[]`，写命令走审批） |
| `plugin.grant` | `{plugin_id, capabilities[]}` | `{plugin}` | 授能力，空数组表示授予清单申请的全部 |
| `plugin.revoke` | `{plugin_id, capabilities[]}` | `{plugin, unloaded}` | 撤能力，撤销关键能力连带卸载 |

**错误码 `6101`–`6109`**（`crates/protocol/src/error.rs`）：

| 码 | 名 | 含义 |
|---|---|---|
| 6101 | `PLUGIN_NOT_FOUND` | 插件未安装 / 未加载（P5 收口后仅此一义） |
| 6102 | `PLUGIN_CRASHED` | 进程不在或刚崩溃，工具已下架 |
| 6103 | `PLUGIN_CAPABILITY_DENIED` | 能力未授予 |
| 6104 | `PLUGIN_API_MISMATCH` | `pluginApi` 版本不兼容 |
| 6105 | `PLUGIN_TIMEOUT` | 调用超时 |
| 6106 | `PLUGIN_PROTOCOL_VIOLATION` | 帧非法 / 方法越权 / 握手不一致 |
| 6107 | `PLUGIN_MANIFEST_INVALID` | 清单非法（`data.details[]`） |

### 2.12 审计日志 `audit.*`

| 方法 | 参数 | 返回 |
|---|---|---|
| `audit.list` | `{session_id?, kind?, since_ms?, until_ms?, limit?, offset?}` | `{events[], total}` |

> 实现注记（M5 切片四）：审计账本落在 `crates/store` 的 `audit_event` 表
> （迁移 `0002_audit_event.sql`），**append-only**：只有 `record_audit` 写入，
> 没有更新 / 删除接口——能被改写的审计等于没有审计。
>
> - **事件类型**（`model::audit_kind`）：`session.created` / `session.updated`
>   （改名或换默认模型）/ `session.deleted` / `session.exported` / `session.forked`。
>   `session.forked` 记在**新会话**上，`detail.source_session_id` 指向源会话。
> - **脱敏**：`summary` 与 `detail` 在**写库前**由 `crates/store/src/redact.rs` 脱敏
>   （键名命中 `api_key` / `token` / `secret` / `password` / `authorization` 等一律打码，
>   文本里的 `sk-…`、`Bearer …`、`api_key=…` 形态被替换为 `***`），**读取时再脱敏一次**
>   兜底老库与手工改动。协议侧返回的值已是安全值，客户端不需要也不应该再处理。
> - **不影响业务**：写审计是旁路，失败只记 `tracing::warn!`，绝不把已成功的
>   会话操作翻成错误（否则会出现「删掉了但报错」）。
> - **查询**：按 `created_at` 倒序（同刻按 `id` 倒序）分页，`total` 是过滤条件下的
>   命中总数、不受 `limit` / `offset` 影响；`limit` 缺省 50、夹到 `1..=500`；
>   `session_id` / `kind` 传空白串等同不过滤；`since_ms > until_ms` 按 `-32602` 拒绝。
> - **留存**：会话删除后审计记录仍在（表上不挂外键、不做级联），这是刻意的。

### 3.1 流式对话

```
Main → Core  workspace.open {path:"E:\\proj"}

Main → Core  llm.chat_stream {stream_id:"s1", messages:[...], model_ref:{...}}

   ... （每 20–50ms 批量推送）
Core → Main  llm.usage     {prompt_tokens:1203, completion_tokens:87}
```

### 3.2 Agent 修改文件（含审批与 diff）

```
Main → Core  agent.start {goal:"给 src/api.ts 的所有请求加超时", mode:"agent", ...}
Core → Main  result {run_id:"r1"}
Core → Main  agent.step_started {step:1, phase:"thinking"}
Core → Main  llm.delta {text:"我先读取文件"}
Core → Main  agent.tool_started {call_id:"c1", tool:"read_file", args:{path:"src/api.ts"}}
Core → Main  agent.tool_finished {call_id:"c1", ok:true, summary:"读取 214 行", duration_ms:12}
Core → Main  agent.step_started {step:2}
Core → Main  agent.diff_proposed {call_id:"c2", diff:{path:"src/api.ts", hunks:[...]}}
Core → Main  agent.approval_required {approval_id:"a1", tool:"edit_file", risk:"medium",
                                      reason:"将修改已存在的文件"}
Main → Core  agent.decide {run_id:"r1", approval_id:"a1", decision:"allow"}
Core → Main  agent.tool_finished {call_id:"c2", ok:true, summary:"应用 2 处修改", artifacts:["src/api.ts"]}
Core → Main  agent.step_started {step:3}
Core → Main  agent.tool_started {call_id:"c3", tool:"run_command", args:{cmd:"pnpm test"}}

Core → Main  agent.tool_finished {call_id:"c3", ok:true, summary:"12 passed", duration_ms:8213}
Core → Main  agent.finished {status:"completed", steps:3}
```

## 5. 版本兼容

- 握手时双方交换 `protocol_version`（`major.minor`）。
- **major 不一致** → Main 拒绝启动 Core 并提示升级。
- **minor 不一致** → 以较低版本能力集为准，未知字段忽略（forward-compatible）。
- 每个 minor 版本的新增方法在 `core.hello` 的 `capabilities` 中声明，UI 按能力开关功能入口。
