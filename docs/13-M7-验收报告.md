### 1.2 切片二：核心接线与工具注入

| 位置 | 内容 |
|---|---|
| `crates/core/src/mcp_manager.rs` | 连接账本 `name → Link`（一 Server 一连接，互不牵连）：`servers` / `connect` / `disconnect` / `tool_infos` / `tool_of` / `client_of` / `call_tool_blocking` / `shutdown_all`。`connect` **幂等**（已 `Ready` 直接回缓存，不重复握手起第二个子进程）；`Stale` / `Closed` 的旧连接**先关再重连**；连上但 `tools/list` 失败则关连接按失败上报并 `record_error`；配置与连接分离，`McpServerInfo` 同时给出 `configured` / `connected` / `state`（`ready` / `stale` / `closed`）；启动时读配置（`%APPDATA%\ai-ide\mcp.json`，`AI_IDE_MCP_CONFIG` 可覆盖），运行期不重读 |
| `crates/core/src/mcp_tools.rs` | `McpToolBridge` 把已连接 Server 的工具包成 `Tool`：注入名必须是 `mcp__<server>__<tool>`（裸名会与核心八工具静默撞车）；`description` / `inputSchema` **原样透传**不规整；**不自做权限判断**——进注册表后与内建工具走同一条 `PermissionGate` → 审批 → `dispatch`，无旁路。`inject(base, manager)` 增量注入，未连接 Server 不产生工具 |
| `crates/core/src/mcp_api.rs` | `mcp.servers` / `connect` / `disconnect` / `tools` / `call` 五个处理器；`McpError` → `8001`–`8007` 按**阶段**（连接期 / 调用期）折码，同一个错误在两侧给不同码；`mcp.call` 的判定顺序是「先连接态、后工具存在」，**`8003` 必须早于 `8004`**（否则模型会去改工具名而不是先 `connect`）；Server 侧 `isError` 属**成功响应**，正文原样回给模型 |
| `crates/core/src/state.rs` | `mcp: OnceLock<Arc<McpManager>>`——「内核没装载 MCP」是显式状态：`mcp.*` 如实回空表 / `8001`，不 panic、不假装成功 |
| `crates/core/src/lib.rs` | 读 `mcp.json` 并把管理器装进状态；**连接是惰性的**（不因配置里写着就在启动时起子进程）；退出前 `shutdown_all` 收尾，不留后台子进程 |
| `crates/core/src/agent_api.rs` | `ToolRegistry::core()` 后接 `mcp_tools::inject(...)`，即每轮现取连接快照；`disconnect` 之后下一轮工具即下架 |
| `crates/protocol` | `mcp.*` 五方法与 13 个 DTO（`McpServerInfo` / `McpServersParams` / `McpServersResult` / `McpConnectParams` / `McpConnectResult` / `McpDisconnectParams` / `McpDisconnectResult` / `McpToolInfo` / `McpToolsParams` / `McpToolsResult` / `McpCallParams` / `McpCallResult` / `McpContentBlock`）；错误码单开 `8xxx`（`8001` Server 不存在 / `8002` 连接失败 / `8003` 未连接 / `8004` 工具不存在 / `8005` 调用失败 / `8006` 超时 / `8007` 参数不可用），与终端 `6001`–`6004`、Git `7001`–`7005` 分段不冲突；`IMPLEMENTED` 56 → **61** |

### 1.5 设计取舍

| 决定 | 理由 |
|---|---|
| `mcp.*` **不新增事件** | 连接/断开是用户显式动作、调用是请求响应，均可由返回值表达；避免与 `workspace.changed` 式的被动刷新叠加出双事件源 |
| 工具注入**不改 Agent 循环** | 注入发生在注册表构造处，Agent 与权限闸门零改动，MCP 工具天然继承既有的审批与审计 |
| `connect` 幂等而非报错 | 外壳按钮重复点击、多窗口同时连接都应无害；重复握手起第二个子进程是真开销 |
| HTTP 侧支持 SSE | 官方远程 Server 多用 SSE 推流，纯 POST 无法完成握手后的服务端推送 |
| 外壳**不订阅 MCP 事件** | MCP 没有自己的推送通道（`workspace.changed` 也不覆盖它——`mcp.json` 是配置不是工作区内容），清单只在进面板 / 刷新 / 连断后拉；宁让用户偶尔点刷新，也不为一个低频视图开轮询 |
| 断开与试跑都在行内**二次确认** | 断开会把该 Server 的工具从 agent 注册表下架，试跑是真的让 Server 干活（写文件、发请求都可能）；连接与刷新是只读发现，不设确认 |
| 参数在渲染侧先校验 | 非法 JSON 就地报「第几处写坏了」，不送去内核换一个 `8007`；`arguments` 只接受 JSON 对象，放宽只会把错误推迟到 Server 内部 |

## 四、缺陷复盘

1. **子 Agent 自述「全绿」不实**：切片二交接时声称 clippy 已过，独立复跑实为 `crates/core/src/mcp_api.rs:196` 的 `&manager` 触发 `clippy::needless_borrow`（`-D warnings` 下直接失败）。教训沿用 M5/M6：**任何门禁结论必须由主 Agent 用重定向日志复跑**，不接受自述。
2. **前端契约与能力清单未同步**：Rust 侧 `IMPLEMENTED` 已 61 项，但 `packages/shared-types` 仍停在 56、`Methods` 无 `mcp` 命名空间、未跑 `types:gen`，`methods-contract.test.ts` 与真实协议脱节。本次补：生成 13 个 `Mcp*` 类型 → `Methods.mcp` 五项 → `IMPLEMENTED_METHODS` 61 → 契约测试三处同步。
3. **`types:gen` 的一次性坑**：脚本用 `cargo test -p ai-ide-protocol export_bindings` 触发 ts-rs 导出后再整体搬迁 `bindings/` 目录；首次运行时命令输出被截断、`bindings/` 已落盘但未搬运，需确认目录内容后再搬。另：删除 `crates/protocol/bindings` 走 `delete`（回收站）而不是 shell 递归删除，符合仓库的删除安全约定。
4. **合并进来的插件原型阻断 lint**：远端 `1ba344b` 的 `demo-plugin-system/run-demo.mjs` 有两条 lint error（`no-useless-assignment` / `preserve-caught-error`）。该目录是**未接线的原型**、不属产品源码，已加入 `eslint.config.mjs` 的 `ignores` 并注明「正式接线时再按 `packages/*` 规则整改」，避免以改原型代码掩盖门禁。

## 五、限制清单

1. **真实 Server 验收依赖外网**：`e2e:m7` 在开发机实测 23/23 通过，但它要 `npx` 拉官方包、要外部网络，故**不入本地/CI 门禁**；离线环境跑不了，且未覆盖企业内网代理场景。
2. **HTTP(SSE) 传输仍未对真实远程 Server 端到端验证**：两个官方 Server 都是 stdio，SSE 侧只有单测（mock）。
3. **配置热重载未做**：改 `mcp.json` 需重启内核才生效（运行期不重读，避免与活连接的状态机打架）；面板只提供「刷新清单」，改配置本身得改文件。
4. **工具风险分级未细化**：MCP 工具进闸门后按内建工具的同一套规则走，但「某个 Server 的写操作该不该默认拒绝」尚无策略，`PermissionGate` 的 `Risk` 由桥统一给出，未按 Server 配置细分。
5. **无连接心跳 / 断线重连**：连接失效依赖下一次调用报错后由用户重建（`Stale` / `Closed` 在下一次 `connect` 时清理），没有后台探测。
6. **工具数量上限未设**：多 Server 全连时注册表可能膨胀，尚无 `max_tools` 截断或优先级裁剪。
7. **面板不渲染富内容**：`mcp.call` 的图片 / 音频块在面板里只显类别与量级，不显示图；真正消费这些块的是 Agent 回灌给模型的路径，已完成。
8. **「模型自主选择 MCP 工具」只用面板试跑与协议层验证**：`e2e:m7` 断言的是「工具以 `mcp__` 前缀进入注册表并可被 `mcp.call` 调用」，未用真实厂商模型跑一次「问一句话 → 模型自己挑 MCP 工具」的对话级用例（可复用 `e2e:m4` 的凭据通道补，尚未做）。
