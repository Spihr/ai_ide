## 四、缺陷复盘（3 条）

### 1. 设置面板 `useEffect` 内同步 `setState`（lint 失败，门禁卡第一步）

- **现象**：外壳侧改动落地后 `pnpm lint` 报 `react-hooks/set-state-in-effect`（1 error）。
- **根因**：`ProviderSettings` 用 `useEffect` 监听 `activeProvider` 并同步 `setState` 初始化表单，形成额外一轮渲染。
- **修复**：抽出 `ProviderForm` 子组件，用 `key={activeProvider?.id ?? 'new-provider'}` 按目标重挂载，表单初值改在 `useState` 初值里给，effect 删除。

### 2. `initAi` 的「已订阅」幂等守卫吞掉全部 `llm.*` 事件（真缺陷，5 例红）

- **现象**：`ai-store.test.ts` 中 4 条流式用例与 1 条取消用例失败——正文一个字不进、状态永远停在「生成中」，而 lint / typecheck 全绿。
- **定位**：先写临时探针（`__probe` / `__probe2`）隔离，直接调 `handleAiEvent` 生效、经 `onAiEvent` 注册的监听收不到 → 问题不在状态机而在订阅环节。
- **根因**：`initAi()` 以 `if (!unsubscribe)` 做幂等。事件源被换过（内核重启、页面重载、preload 重新注入）后旧退订句柄仍在，「已订阅」判断为真而实际订阅指向失效的事件源，`llm.*` 事件全部丢失。
- **修复**：`initAi()` 改为总是先 `disposeAi()` 再重新订阅；探针确认后删除。
- **为什么单测没拦住**：每个用例各自装桩、单次订阅，自洽即通过；守卫缺陷只在「事件源被替换 + 二次 init」时暴露。已由修复后的用例（`provider.changed` 触发清单重拉、流式收口等）间接覆盖。

### 3. 类型漂移三处（typecheck 失败）

- **现象**：`typecheck` 报 `ProviderProtocol` 不接受 `'openai'`（合法值为 `openai_chat_completions` 等）；`store.test.ts` 的假 `aiide` 缺 `getCredentialStatus` / `forgetCredential` / `onAiEvent` / `onCredentialStatus`；`CoreSupervisorOptions` 无 `env`。
- **修复**：测试改用生成枚举的真实值；假对象补齐 4 个凭证/事件方法；`CoreSupervisorOptions` 补 `env?: NodeJS.ProcessEnv`。
