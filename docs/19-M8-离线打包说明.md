# M8 离线 / 受限网络打包说明

> 对象：`E:\ai_ide` 的打包链路（electron-builder 26.15.3 + Electron 44.9.0）
> 用途：在**无法访问 GitHub / 网关受限**的机器上，稳定复现 `win-unpacked` 与 NSIS 安装器
> 脚本：[`scripts/offline-pack.mjs`](../scripts/offline-pack.mjs)
> 关联报告：[`15-M8-验收报告.md`](./15-M8-验收报告.md) §五.1、[`18-M8-真机安装验收清单.md`](./18-M8-真机安装验收清单.md) §七

---

## 一、问题：`pnpm dist` 在网络受限机必挂

`.npmrc` 里已有 `electron_mirror=https://npmmirror.com/mirrors/electron/`，但它**只作用于 `electron` npm 包自身的 postinstall**（下载 electron 本体）。electron-builder 内置的二进制下载器**不读** `.npmrc` 的 `electron_mirror`，出包时仍会去 GitHub 拉：

| 下载物 | 默认来源 | `.npmrc` 的 `electron_mirror` 是否生效 |
|---|---|---|
| `electron` npm 包 postinstall（解包 dist） | `electron_mirror` | 是 |
| electron-builder 打包阶段（`--dir` / NSIS）的 electron 压缩包 | GitHub Releases | **否** |
| NSIS / winCodeSign 等 builder 附加资源 | GitHub Releases | **否** |

因此典型失败形态是：`pnpm install` 正常，`pnpm dist` 在 `downloading electron` 或 `downloading nsis` 阶段超时。

---

## 二、绕行：两条开关固化进脚本

`scripts/offline-pack.mjs` 把两条绕行做成一次调用，不再手敲长参数：

| 绕行 | 做法 | 解决的问题 |
|---|---|---|
| ① 本地 electron dist | 自动探测 `node_modules`（含 pnpm `.pnpm` 目录）里已解包的 electron，传 `--config.electronDist=<该 dist 绝对路径>` | 打包阶段**完全不下载** electron 本体 |
| ② builder 镜像 | 注入 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`（若已显式设置则沿用，不覆盖） | NSIS / winCodeSign 等附加资源不再走 GitHub |

脚本行为：

1. 从 `apps/desktop/package.json` 读 `electron` 声明版本，按「精确版本 → 同主版本」在 `node_modules/electron/dist`、`node_modules/.pnpm/electron@<ver>/node_modules/electron/dist` 中定位 dist；
2. Windows 判据为 `dist/electron.exe` 存在（非 Windows 判 `dist/electron`），找不到直接失败并给出处理建议，**不会退回联网下载**；
3. 以 `apps/desktop` 为 cwd 调用 electron-builder（`electron-builder.yml` 的相对路径语义不变）；
4. 支持 `--dir` 透传给 electron-builder，以及 `--dry-run` 只打印探测结果与将执行的命令。

## 三、命令

```powershell
# 出免安装目录（前端已构建 + 内核已 prepack 后）
pnpm package:dir:offline

# 出 NSIS 安装器（推荐）
pnpm dist:offline

# 只看脚本探测到了什么、要执行什么命令，不打包
node scripts/offline-pack.mjs --dry-run
node scripts/offline-pack.mjs --dir --dry-run
```

`package:dir:offline` / `dist:offline` 与在线版 `package:dir` / `dist` 的唯一差别，是最后一步从
`pnpm --filter @ai-ide/desktop package:dir|dist` 换成 `node scripts/offline-pack.mjs [--dir]`；
前置的 `verify:versions` → `prepack:core`（内核 release 二进制复制到 `apps/desktop/build/core`）→ `electron-vite build` 完全一致，产物校验也一致（`verify-package.mjs`）。

> 若只想临时用一次、不改脚本：
> ```powershell
> $env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
> pnpm --filter @ai-ide/desktop exec electron-builder --dir --config.electronDist=(Resolve-Path apps\desktop\node_modules\electron\dist).Path
> ```

## 四、前置条件与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `未找到本地 electron dist（声明版本 ^44.9.0）` | 依赖未装，或 dist 被 `nnpm` 缓存清理掉 | 先 `pnpm install`（`.npmrc` 的 `electron_mirror` 会接管 electron 本体下载），再重跑 |
| `downloading nsis-3.x.x.7z` 仍然超时 | 环境变量被外部置空，或镜像站不可达 | 确认 `ELECTRON_BUILDER_BINARIES_MIRROR` 未被设成空串；必要时换回默认源 |
| `author is missed in the package.json` | 历史告警，不影响出包 | 忽略（`apps/desktop/package.json` 未填 author） |
| `packageManager not detected ... resolvedPackageManager=npm` | electron-builder 在 `apps/desktop` 找不到 lockfile | 忽略；`electron-builder.yml` 已设 `npmRebuild: false`，不触发 npm 重建 |
| 产物仍缺内核 | 跳过了 `prepack:core` 直接跑脚本 | 本脚本不负责构建内核，请走 `pnpm dist:offline` 全链路，或先 `node scripts/prepack-core.mjs` |
| `EPERM: operation not permitted, unlink '...\win-unpacked\AI IDE.exe'` | 上一版 `win-unpacked` 里的 `AI IDE.exe` 正在运行（用户从 `release\win-unpacked` 直接启动了应用） | 先退出运行中的包版本再重打；三处占用是 `AI IDE.exe`（主进程 + 子进程）与 `resources\core\ai-ide-core.exe` |
