## 四、M4 期间缺陷复盘（3 条）

### 1. 两处质量门禁红（`242db47`）

- `crates/protocol/src/dto.rs` 触发 `clippy::needless_borrows_for_generic_args`；TS 侧 `methods-contract.test.ts` 左值缺 5 个 agent 常量，`pnpm test` 失败。根因是「协议面先行、两端补齐滞后」：方法常量与 DTO 分属两个提交落地，中间态未被门禁拦住。
- 处置：借用冗余改为直接传值；常量补齐并把字符串字面量双向锁定，避免只补一侧再次漂移。

### 2. `cargo fmt --check` 未纳入自检（本轮修复）

- 本轮把 `cargo fmt --all -- --check` 补进收口门禁后，`crates/core/src/agent_api.rs`、`crates/agent/src/runner.rs` 报格式偏差——此前三个 M4 提交只跑了 clippy / test，未跑 fmt。
- 处置：`cargo fmt --all` 归一化，并把 fmt 放在收口门禁的首位；后续提交按 `fmt → clippy → test → build → smoke` 顺序自查。

### 3. 空路径被误判越界，`list` 工具在默认工作目录下直接致命终止（`e17c8cf`，联调时暴露）

- 现象：真机联调的第一轮，模型调 `list({"path": ""})`（想列当前工作目录），闸门把空串拿去和 workspace 根比对，判成**越界路径**并按越界处置（硬拒 + 终止循环），整条运行以 `status=failed` 收工；同一逻辑在脚本化假模型用例里没被覆盖，因为那些用例都显式传了非空 `path`。
- 影响面：所有只读工具（`list` / `read` / `grep`）都会撞上，属**默认用法即触发**的阻断性缺陷；后果是「模型只要省略 path 就整轮失败」。
- 根因：`ruling_for_path` 把「字段缺失 / 空串」与「越界」混为一谈——空串没有做 `is_empty` 过滤就进入路径解析，解析结果为空 PathBuf，落在 workspace 根之外。
- 处置：`permission.rs` 里把空串视作「没给路径」，交给工具自身按工作目录兜底；新增单测 `blank_path_is_treated_as_no_path` 锁定行为（同时验证真实越界路径仍被拒，避免为修这个洞而放宽越界判定）。
- 复盘价值：这条缺陷只能靠真机联调暴露，印证了硬指标 1 的必要性——假模型用例按「理想参数」构造输入，覆盖不到模型真实调用习惯（少传 / 传空）。

## 五、如实记录的限制（8 处）

① **clippy 输出含 8 条构建期噪声**：`warning: failed to parse serde attribute`（`ts-rs` 派生相关）。命令退出码为 0，未判负；根因未深挖。
② **真实模型联调只覆盖单一模型**：本轮只验了网关选定的 `deepseek-v4-pro`（网关 `/v1/models` 返回 42 个可用模型），未做多模型复测，因此「4/4」「20/20」是**该模型下**的实测结论，不能外推为全模型能力；换小模型可能退化。
③ **上游存在偶发失败**：5 次全量运行中有 1 次因上游返回 `HTTP 502: 代理转发失败` 导致任务 2 未收工（该次任务 2 的 5 条内容断言全过、3 处 `fetch` 也都改对了，只是收尾请求失败），脚本按失败如实记录、不做重试粉饰。稳定性描述见七-5。
④ **Unix 侧 `run_command` 超时只杀直接子进程**：Job Object + `taskkill /T /F` 的杀树保障仅 Windows 生效，Unix 分支退化为 `kill`（`run_command.rs` 文件头已注明偏离）。
⑤ **工具调用卡片未组件化**：参数、状态、耗时、输出展开以内联渲染承载，无独立卡片组件（docs/05 M4 任务 6 的实现形态差异）。
⑥ **`crates/packages/shared-types` 重复生成物已清理**：18 个被 git 跟踪的陈旧 TS 生成物与 `packages/shared-types/src/generated/` 同名文件**14 个字节一致、4 个（`ErrorObject` / `Notification` / `Request` / `Response`）仅 1 行 import 路径差异**（指向 `crates/protocol/bindings/serde_json/`），全仓无任何引用，非 pnpm workspace 成员。已删除（删除前均在 git 历史中，可随时恢复）。
⑦ **基线任务每条只采样 1 次**：不做多次取均值，耗时与 token 受上游抖动影响明显（同一任务跨运行 11.5s–20.1s），因此第七节的耗时只作量级参考，**不构成性能基线**。
⑧ **20 个 `edit_file` 用例是按指标定义构造的样本**，非自然分布下的随机抽样：首轮锚点由提示词强制为歧义整行锚点（`timeout: 1000`），重复处数限定 2–4、目标位置分布在 1–4 处（实际 5/12/2/1），且沙箱内用 `node test.mjs` 等价替代 docs/05 的 `pnpm test`。
