## 四、缺陷复盘（本轮 5 条）

### 1. 分叉后的提示被「切会话」清掉（外壳）

- 现象：`forkSession` 先写 `hint`（「已从…分叉」）再 `selectSession`，而 `selectSession` 开头会清空提示位，用户看不到任何反馈，只看列表多了一条。
- 根因：状态写入顺序与「打开会话会重置会话级 UI 状态」的既有约定冲突，单测只断言了「列表插入了新会话」，没断言提示是否还在。
- 处置：改为 `selectSession` 成功后再写 `hint`；`session-store.test.ts` 的「分叉出新会话后直接切过去」同时断言提示与气泡。

### 2. 测试用例在没有初值的情况下断言列表（测试自身缺陷）

- 现象：`session-store.test.ts` 首轮 4 个用例红，失败点是「列表为空」，业务代码无问题。
- 根因：store 是模块级单例，`resetSessionState()` 只清状态不拉数据，用例直接断言 `sessions` 而未先 `refreshSessions()`；`ai-store.test.ts` 早有 `initAi()` 的同类前置约定，新模块漏搬。
- 处置：`beforeEach` 中统一 `resetSessionState()` + `refreshSessions()`，并在文件头注明「store 是单例，每个用例必须自己拉初值」。

### 3. 接口扩容漏改手写测试替身（流程问题）

- 现象：`AiIdeApi` 增加 `pickSavePath` 后，`store.test.ts` 与 `agent-store.test.ts` 里手写的假 API 对象没跟上，`pnpm typecheck` 报缺字段；`session-store.test.ts` 用统一 harness，未受影响。
- 根因：两个替身是各自手写的对象字面量，而非从 `AiIdeApi` 派生，接口扩容时不会连带报错。
- 处置：两处各补 `pickSavePath: async () => null` 并注明「落点由主进程系统对话框决定，渲染侧只拿返回值」；本地门禁顺序固定为 `fmt → clippy → test → lint → typecheck → build → smoke → e2e:m1`。

### 4. P0 门禁阶段：clippy 4 处、fmt 41 处、前端 2 处用例缺口

- 现象：M5 三个缺口落地后本地门禁未跑，`clippy` 在 `checkpoint.rs`（2 处）与 `logging.rs`（2 处）报错；`cargo fmt --check` 报 41 处格式差异；`pnpm test` 有 2 个用例红。
- 根因：新增切片只跑了 `cargo test`，没跑 `fmt` / `clippy`；前端 `permission.list` / `permission.revoke` 已接进外壳，但 `methods-contract.test.ts` 与 `policy.test.ts` 两个手写清单没同步补上，两处断言失败。
- 处置：修完 4 处 clippy 与 41 处格式、两个前端用例补齐后拆成 7 个提交（`b068e33` → `85e6829`），门禁四件套复测全绿。

### 5. 满负载下 `permission_flow` 出现过一次「会话库未就绪」（已定位，已修复）

- 现象：本轮 `pnpm verify:m5` 的 `cargo test --workspace` 一跑中，`crates/core/tests/permission_flow.rs` 的 `revoke_by_id_and_by_tool` 失败 1 次，报 `5002 会话库未就绪：落盘目录不可写或迁移失败`；同一次运行其余 684 项全过。
- 现场：该用例先用测试进程自己的连接把规则写进同一个 `sessions.db`，再拉起内核子进程去 `permission.list` / `permission.revoke`；失败点在内核侧打开库，而不是断言不匹配。
- 当时为何没能复现：单独跑该测试通过；随后 6 次连续单跑 + 4 次并发 `-p ai-ide-store` 压力共 0 失败；再跑一次完整 `cargo test --workspace` 685 项全过。失败概率与机器负载、CI runner 冷启动速度相关，本地空载跑不出来。
- **根因（两处缺陷叠加）**：
  1. **两个进程对同一个库并发迁移**：用例由测试进程自己的连接写种子规则，同时 `Core::spawn` 拉起的内核子进程在 `Store::connect` 里跑 `MIGRATOR.run`。二者对着同一个 `sessions.db` 同时迁移，CI runner 冷启动慢时抢锁超时，内核侧迁不上去即退化为 `5002 会话库未就绪`。这与「满负载才出现」完全吻合。
  2. **临时数据目录重号导致互删**：测试脚手架的 `TempDir::new` / `TempDataDir::new` 用「`pid` + `SystemTime::now()` 纳秒」拼目录名，而 Windows 上该时钟实际粒度可达毫秒级，同一测试二进制里并发跑的用例会取到完全相同的值。目录同名后，先结束的那个 `Drop` 把另一个正在使用的目录整个删掉，表现同样是「落盘目录不可写 / 迁移失败」，掩盖了根因 1。
- **修复（三处，已在本地验证）**：
  - `permission_flow.rs` 的 `revoke_by_id_and_by_tool` 与 `lists_rules_written_from_another_connection` 在 `Core::spawn` 后先调一次 `core.capabilities()` 握手，等内核把迁移落库之后再写种子规则，并发迁移消失。
  - `tests/common/mod.rs` 新增 `static TEMP_DIR_SEQ: AtomicUsize` 与 `pub fn unique_temp_dir(prefix, tag)`，用进程内原子序号替代纳秒时间戳（返回前先清同名残留）；`audit_flow` / `checkpoint_flow` / `git_flow` / `permission_flow` / `session_export_flow` / `session_flow` 六个文件的 `Temp*::new` 全部改走它，同进程内绝不再重号。
  - `ci.yml` 的单元测试步骤显式设 `AI_IDE_TEST_CORE_LOG=${{ runner.temp }}\core-logs` 并预建目录，再加一步「上传内核日志（失败时）」用 `upload-artifact@v4` 收走日志（保留 7 天）。内核 stderr 原本被测试脚手架丢弃，失败时只剩一句笼统断言，这一步保证下次真出问题能直接拿到现场。
- 验证：`cargo fmt --all -- --check` 与 `cargo clippy --workspace --all-targets -- -D warnings` 通过；`cargo test --workspace` 40 个测试二进制 **950 passed / 0 failed**；带 `AI_IDE_TEST_CORE_LOG` 实跑确认按进程分文件产出 `core-<pid>-<seq>.log`，内容含「会话库已就绪」。
- 残留风险：修复针对的是「跨进程并发迁移」与「目录重号」两条已知路径；日志上传只覆盖 CI，若将来出现第三种成因，仍需靠 artifact 里的内核日志定位。

内核侧无功能返工：`crates/store` 与 `crates/core` 的 M5 代码自首次提交起未因缺陷重建，返工集中在外壳状态时序、测试前置条件、替身同步与门禁补齐。

## 五、如实记录的限制（10 处）

① **检查点只覆盖「登记过」的文件**：回滚只写回登记列表里的文件，不删登记之后新建的文件；检查点也没有保留期与自动清理，`checkpoint.delete` 或手工清盘由用户决定。

② **检查点有三档硬上限**：单文件 > 8 MiB、单检查点 > 5000 个文件、总量 > 256 MiB 的部分会被跳过，并在结果里如实回报（不静默截断），但意味着大仓库里的超大文件不受保护。

③ **检查点无增量去重**：每次 `checkpoint.create` 都是整份复制，同一个文件改 10 次就是 10 份；也没有压缩。

④ **日志没有保留期**：按天 + 32 MiB 滚动，但不自动删除旧文件、不压缩；`AI_IDE_LOG_REDACT=0` 能关掉脱敏（默认开），关掉时日志里会出现明文密钥。

⑤ **权限表只记「总是允许」**：`deny` 不落库（默认就是拒）；这张表既不放大也不收窄默认策略，只负责「这一次别再问我」，撤销只作用于免问集合。

⑥ **分叉只有「从会话末尾」一个入口**：协议与内核支持 `from_message_id`，但 `SessionPanel` 固定传 `null`，消息级分叉没有 UI 入口。

⑦ **列表与审计都是首页制**：会话列表固定 `limit=50`、审计固定 `limit=20`，二者都只拉 `offset=0`，UI 无「加载更多」；超过页长的条目要靠搜索词收窄才能看到。

⑧ **会话搜索是标题过滤**：`session.list` 的 `query` 只匹配标题，不检索消息内容。

⑨ **消息落盘不做重试**：`session-bridge.ts` 明确选择「失败只报一次、不重试」，理由是重试会把一条消息写两遍的概率换成「历史里多一条重复消息」；代价是网络或库抖动会静默丢一条历史（UI 有提示，库里没有）。

⑩ **单窗口假设**：活动会话 id 是渲染进程模块级单例，多窗口会各自持有一份；当前应用只开一个主窗口，未做跨窗口同步。
