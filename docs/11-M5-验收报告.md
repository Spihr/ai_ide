## 四、M5 期间缺陷复盘（3 条）

### 1. 分叉后的提示被「切会话」清掉（外壳）

- 现象：`forkSession` 先写 `hint`（「已从…分叉」）再 `selectSession`，而 `selectSession` 开头会清空提示位，用户看不到任何反馈，只看列表多了一条。
- 根因：状态写入顺序与「打开会话会重置会话级 UI 状态」的既有约定冲突，单测只断言了「列表插入了新会话」，没断言提示是否还在。
- 处置：改为 `selectSession` 成功后再写 `hint`；`session-store.test.ts` 的「分叉出新会话后直接切过去」同时断言提示与气泡。

### 2. 测试用例在没有初值的情况下断言列表（测试自身缺陷）

- 现象：`session-store.test.ts` 首轮 4 个用例红，失败点是「列表为空」，业务代码无问题。
- 根因：store 是模块级单例，`resetSessionState()` 只清状态不拉数据，用例直接断言 `sessions` 而未先 `refreshSessions()`；`ai-store.test.ts` 早有 `initAi()` 的同类前置约定，新模块漏搬。
- 处置：`beforeEach` 中统一 `resetSessionState()` + `refreshSessions()`，并在文件头注明「store 是单例，每个用例必须自己拉初值」。

### 3. 接口扩容漏改手写测试替身（流程问题）

- 现象：`AiIdeApi` 增加 `pickSavePath` 后，`store.test.ts` 与 `agent-store.test.ts` 里手写的假 API 对象没跟上，`pnpm typecheck` 报缺字段；`session-store.test.ts` 用统一 harness，未受影响。
- 根因：两个替身是各自手写的对象字面量，而非从 `AiIdeApi` 派生（如 `satisfies AiIdeApi`），接口扩容时不会连带报错。
- 处置：两处各补 `pickSavePath: async () => null`，并注明「落点由主进程系统对话框决定，渲染侧只拿返回值」；本轮门禁顺序固定为 `fmt → clippy → test → lint → typecheck → build → smoke → e2e:m1`。

内核侧无功能返工：`crates/store` 与 `crates/core` 的 M5 代码自首次提交起未因缺陷重建，返工集中在外壳状态时序、测试前置条件与上面这处替身同步。文档与状态同步（本报告、README、docs/00）属本轮收尾的一部分，不计为缺陷。

## 五、如实记录的限制（8 处）

① **检查点回滚未实现**：docs/05 的 M5 任务 3 完全未开工，M4 遗留的「强制 diff 预览 + 检查点回滚」中的后者仍缺，Agent 改坏文件的唯一兜底仍是 git 与用户自身备份。

② **结构化日志未实现**：只有审计事件表，无 JSONL 文件、无按天滚动、无脱敏开关；因此 docs/05 的「日志不含 API Key」仅能就审计路径给出证据。

③ **权限表未持久化**：`allow_always` 的作用域是单次进程内运行，重启即失效；docs/05 提的权限表本轮未建。

④ **分叉只有「从会话末尾」一个入口**：协议与内核支持 `from_message_id`，但 `SessionPanel` 固定传 `null`（`forkSession(session.session_id, null)`），消息级分叉（从某条消息处切开）没有 UI 入口，`session-store.ts` 的该参数目前只有测试在用。

⑤ **列表与审计都是首页制**：会话列表固定 `limit=50`、审计固定 `limit=20`，二者都只拉 `offset=0`，UI 无「加载更多」；超过页长的会话在面板里看不到，需要用搜索词收窄。

⑥ **会话搜索是标题过滤**：`session.list` 的 `query` 只匹配标题，不检索消息内容；找「上周那轮聊到 X 的对话」只能靠标题。

⑦ **消息落盘不做重试**：`session-bridge.ts` 明确选择「失败只报一次、不重试」，理由是重试会把一条消息写两遍的概率换成「历史里多一条重复消息」；代价是网络或库抖动会静默丢一条历史（UI 有提示，库里没有）。

⑧ **单窗口假设**：活动会话 id 是渲染进程模块级单例，多窗口会各自持有一份；当前应用只开一个主窗口，未做跨窗口同步。
