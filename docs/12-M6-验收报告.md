# M6 验收报告：终端与 Git

> 日期：2026-10-22
> 范围：`crates/terminal`（内核终端）、`crates/git`（内核 Git）、`crates/protocol` 十个方法与两条事件、`crates/core` 接线（`terminal_api.rs` / `git_api.rs` / `state.rs` / `dispatch.rs` / `lib.rs`）、`apps/desktop` 外壳三层（main 事件路由与策略、preload 暴露面、renderer 终端面板与 Git 面板）、质量门禁与文档同步
> 结论：M6 四个切片（内核终端 → 外壳终端面板 → 内核 Git → 外壳 Git 面板）全部落地。能力清单 30 → **46 → 51 → 56**（M5 结束时 46，M6 新增 5 个 `terminal.*` + 5 个 `git.*`），`DECLARED_NOT_IMPLEMENTED` 仍为空表。docs/05 的 M6 两条验收指标中，「Git 面板能显示变更并提交」在**自动化层面**已闭环（内核端到端全链路 + 外壳状态机与解析单测），「终端交互无卡顿、resize 正确」仅有 resize 参数传递与夹取的**自动化证据**，**无真机主观体感实测**（见第五节限制清单）。

## 四、缺陷复盘

1. **`WorkspaceChangedEvent` 形状写错导致 typecheck 失败**：测试里按旧结构造了 `{ workspace_id, kind, paths, index_dirty, at_ms }`，实际生成的 DTO 只有 `{ workspace_id, changes[] }`，`as` 转换被 TS 判为不存在重叠而报错。教训：外壳测试造事件必须对齐 `packages/shared-types/src/generated/`，不要凭印象写字段。
2. **`noUncheckedIndexedAccess` 下的数组取值**：`hunks[0].oldLine`、`callsOf(...)[0].params` 这类断言在严格索引检查下会被判为 `undefined`，统一改为可选链后类型收窄。教训：外壳测试访问数组元素一律用 `?.`，否则 typecheck 阶段才暴露、build 阶段不报（本轮即「build 先绿、typecheck 后红」）。
3. **`initGit` 的订阅归属**：初版只在面板挂载时订阅 `workspace.changed`，面板未打开时切换工作区会漏刷新；改为在回调里比对 `activeWorkspaceId()` 与事件 `workspace_id`，事件与活动工作区不一致即丢弃。
4. **`git.*` 白名单遗漏**：`policy.ts` 先只放了 `terminal.*`，Git 面板调用会被第二道闸门拦成 `forbidden`；已补白名单并加最小集断言，防止后续再漏。
5. **`permission_flow::revoke_by_id_and_by_tool` 偶发 5002（已定位，已修复）**：本切片首次跑全量 `cargo test --workspace` 时该用例报「会话库未就绪：落盘目录不可写或迁移失败」，单独复跑该测试文件与随后重跑全量均通过（783 passed / 0 failed）。当时判断为「既有（M5）用例的临时数据目录竞争、与本次 Git 外壳改动无关」——方向对，但与 `git_flow` 用的是同一套脚手架，所以没在本切片里就此收口。后续按 `docs/11` §5 的现场继续排查，确认是**两处缺陷叠加**：
   - **两个进程对同一个库并发迁移**：用例由测试进程自己的连接把种子规则写进 `sessions.db`，而 `Core::spawn` 拉起的内核子进程同时在 `Store::connect` 里跑 `MIGRATOR.run`。两者对同一库并发迁移，CI runner 冷启动慢时抢锁超时，内核迁不上去即退化为 5002。
   - **临时目录重号导致互删**：`Temp*::new` 用「`pid` + `SystemTime::now()` 纳秒」拼目录名，Windows 上该时钟实际粒度可达毫秒级，同一测试二进制内的并发用例会取到相同值；同名目录下先结束的 `Drop` 会删掉另一个正在使用的目录，症状同样是「落盘目录不可写 / 迁移失败」，把前一成因盖住了。
   - 修复三处：`permission_flow` 的两个用例在 `Core::spawn` 后先 `core.capabilities()` 握手再写种子；`tests/common/mod.rs` 新增 `unique_temp_dir`（`AtomicUsize` 序号）并让 `audit` / `checkpoint` / `git` / `permission` / `session_export` / `session_flow` 六个文件统一改走它；`ci.yml` 设 `AI_IDE_TEST_CORE_LOG` 并新增失败时 `upload-artifact@v4` 上传内核日志。验证：`fmt` / `clippy -D warnings` / `cargo test --workspace`（950 passed / 0 failed）全通过，日志实测落盘且含「会话库已就绪」。

## 五、限制清单（如实记录）

1. **无真机界面验收**：本轮未在 Electron 窗口里做人工点击（真实仓库的变更列表、diff 滚动、提交按钮），全部结论来自内核端到端 + 外壳单测 + 构建通过。真实 UI 的卡顿 / resize 主观体验、Monaco 与 xterm 同屏时的布局抢占**未实测**。
2. **`git.*` 能力面有限**：未实现分支切换 / 新建 / 删除、拉取 / 推送、stash、单 hunk 暂存、冲突解决（编辑器只展示冲突状态字母）。`git.diff` 单次 1 MiB 截尾，超大文件 diff 不完整（面板显示 `truncated` 提示）。
3. **状态刷新靠 `workspace.changed` + 400 ms 去抖**：仓库外部的 `git` 命令（用户在外部终端 `git commit`）不会触发 `workspace.changed` 之外的路径，若只改动 `.git/` 内部（如纯 `commit` 不碰工作区文件），面板需手动刷新。
4. **未跟踪文件的 diff**：内核不产出未跟踪文件的内容 diff，面板显示「未跟踪，暂存后可查看 diff」提示，需先暂存。
5. **提交只支持整批**：`git.commit` 只提交已暂存内容（可选 `paths[]` 但外壳未暴露该入口），不支持「只提交部分文件」的 UI 交互。
6. **无 M6 端到端验收脚本**：M4 / M5 均有 `pnpm e2e:*` 真实链路脚本，M6 只有内核 `cargo test` 端到端与外壳 vitest，**没有跑真实 Electron 窗口的 Playwright / e2e 用例**。
7. **Windows 为主**：`git` 子进程与终端 PTY 只在 Windows 11 上验证，macOS / Linux 的 `sh` 路径与换行差异未实测。
