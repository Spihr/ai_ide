## 2. 各阶段详细计划

### M0 骨架与通信（**已完成**，实测见 [`06-M0-验收报告.md`](./06-M0-验收报告.md)）

**任务**

3. `crates/protocol`：定义 JSON-RPC 帧结构 + DTO，导出 JSON Schema → 生成 TS 类型。
4. `crates/core`：tokio 主循环，读取 stdin 行 → 分发 → 写 stdout；实现 `core.hello` / `core.ping`。

**验收**

- 协议类型生成后，TS 与 Rust 编译均通过（无手写重复定义）。

### M1 编辑器壳（**已完成**，实测见 [`07-M1-验收报告.md`](./07-M1-验收报告.md)）

**任务**

4. 文件读写（编码探测、EOL 保持、乐观锁 hash）。

**验收**

### M2 模型接入（预计 4–5 天）

**任务**

5. 对话面板：消息流、Markdown + 代码高亮、流式批量刷新（50ms 合并）、停止生成。

**验收**

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 各家 API 工具调用协议差异大 | Agent 在部分厂商上不可用 | Provider 归一化层 + 用"仅文本模式"降级（无工具调用时退化为 Chat） |
| 模型幻觉导致编辑错位 | 改坏用户代码 | 唯一匹配 + 上下文校验 + 强制 diff 预览 + 检查点回滚 |
| 大仓库索引慢 | 首次体验差 | 阶段性索引（先给文件树，后台增量索引）+ 进度事件 + 可关闭索引 |
| Electron 包体积与内存 | 用户抱怨 | 可接受（~150MB）；内存目标 < 600MB，用 `--max-old-space-size` 与懒加载控制 |
| Rust 与 TS 类型漂移 | 隐性 bug | protocol crate 单一来源 + CI 校验生成物无 diff |
| 命令执行安全 | 误删数据 | 双闸门 + 黑名单 + 回收站 + 工作区边界 + 超时 |
| 长会话上下文爆炸 | 请求失败或成本失控 | 5 级压缩 + 预算上限 + 用量可见 |
