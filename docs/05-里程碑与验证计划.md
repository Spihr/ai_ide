# 里程碑与验证计划

> 文档版本：v0.1（待审阅）
> 原则：**每个里程碑必须产出可运行、可验证的东西**，不允许"只写代码不验收"。

---

## 1. 里程碑总览

| 里程碑 | 主题 | 交付物 | 验收标准（硬指标） |
|---|---|---|---|
| M0 | 骨架与通信 | Monorepo 脚手架、Electron 空壳、Rust 内核空壳、握手打通 | 应用启动 3s 内可交互；`core.hello` 成功；`core.ping` RTT < 5ms；CI 绿 |
| M1 | 编辑器壳 | 工作区打开、文件树、Monaco 多标签、保存、搜索 | 打开 1 万文件工作区 < 3s；编辑 1 万行文件输入 < 16ms；保存后磁盘内容一致 |
| M2 | 模型接入 | Provider 配置 UI、密钥加密、流式对话 | 首个 Provider 连接测试通过；流式首 token < 2s；密钥明文不出现在任何文件中（可验证） |
| M3 | 上下文引用 | `@文件/@文件夹/@选区/@当前文件`、token 计数、压缩 | 引用 5 个文件时正确注入且 token 计数误差 < 3%；超限自动压缩不报错 |
| M4 | Agent 闭环 | 6 个核心工具、权限审批、diff 预览与应用 | 完成"找到函数→改超时→跑测试"端到端任务；`edit_file` 唯一匹配失败时自动重试成功 |
| M5 | 持久化与治理 | 会话 SQLite、导出、审计日志、检查点回滚 | 重启后会话完整恢复；回滚可精确还原文件字节；审计记录完整 |
| M6 | 终端与 Git | xterm.js 终端、Git 状态与 diff | 终端交互无卡顿、resize 正确；Git 面板能显示变更并提交 |
| M7 | MCP | stdio + HTTP 双传输、工具注入 | 连接 2 个官方 MCP Server 并成功调用其工具 |
| M8 | 打包分发 | electron-builder 安装包（含 Rust 二进制） | 干净 Windows 机器上安装即用；无缺失运行库 |

## 2. 各阶段详细计划

### M0 骨架与通信（**已完成**，实测见 [`06-M0-验收报告.md`](./06-M0-验收报告.md)）

**任务**
1. 初始化 `pnpm workspace` + `cargo workspace`。
2. `apps/desktop`：electron-vite 脚手架，主进程/预加载/渲染三端可编译。
3. `crates/protocol`：定义 JSON-RPC 帧结构 + DTO，导出 JSON Schema → 生成 TS 类型。
4. `crates/core`：tokio 主循环，读取 stdin 行 → 分发 → 写 stdout；实现 `core.hello` / `core.ping`。
5. Main 侧 `CoreSupervisor`：拉起子进程、握手、心跳、退出清理。
6. CI：lint（`cargo clippy -D warnings` + `eslint`）、单测、构建。

**验收**
- `pnpm dev` 单命令启动完整链路。
- 集成测试：Main 发 `core.ping` × 100 次全部成功。
- 协议类型生成后，TS 与 Rust 编译均通过（无手写重复定义）。

### M1 编辑器壳（**已完成**，实测见 [`07-M1-验收报告.md`](./07-M1-验收报告.md)）

**任务**
1. 布局骨架（活动栏 / 侧栏 / 编辑器区 / 状态栏）。
2. `workspace.open` + 文件树（懒加载、`.gitignore` 灰显、图标）。
3. Monaco 集成：多标签、脏标记、快捷键（保存/关闭/切换）、主题。
4. 文件读写（编码探测、EOL 保持、乐观锁 hash）。
5. 搜索：文件名模糊（`search.files`）+ 内容检索（`search.content`，ripgrep 语义）。
6. 文件监听 → `workspace.changed` → 树与标签的"外部已修改"提示。

**验收**
- 10 万文件目录（脚本生成）从打开到树首屏 < 3s，全量索引 < 30s。
- 编辑大文件输入延迟用 DevTools Performance 测量 < 16ms/frame。
- 手动在资源管理器改文件后，IDE 1s 内提示冲突。

### M2 模型接入（**已完成**，实测见 [`08-M2-验收报告.md`](./08-M2-验收报告.md)；原估 4–5 天）

**任务**
1. `crates/llm`：`Provider` trait + OpenAI Chat Completions 实现（SSE 解析）。
2. `provider.*` / `model.*` 方法 + SQLite 落库。
3. 密钥加密：Main 侧 safeStorage，Core 侧仅内存持有。
4. 设置 UI：Provider 列表/编辑表单/连接测试/模型管理与能力标注。
5. 对话面板：消息流、Markdown + 代码高亮、流式批量刷新（50ms 合并）、停止生成。
6. 错误呈现：401/429/超时/上下文超限分别给可操作提示。

**验收**
- 连接测试对 OpenAI 兼容端点返回真实延迟与模型数。
- 用 `rg` 全盘搜索临时目录，确认 API Key 明文零命中。
- 断网/错 Key/超长上下文三种异常路径均有可读提示，UI 不崩。
- **契约测试**：对 SSE 解析器喂 6 类真实响应的录制样本，断言事件序列正确。

### M3 上下文引用（**已完成**，实测见 [`09-M3-验收报告.md`](./09-M3-验收报告.md)；原估 3–4 天）

**任务**
1. `@` 引用解析器（输入框内的高亮与补全菜单）。
2. 引用内容解析：文件（含裁剪策略）、文件夹（目录树 + 签名）、选区、当前文件窗口上下文。
3. `tiktoken-rs` 计数 + 预算分配 + 5 级压缩策略。
4. `crates/parser`：tree-sitter 接入（TS/Python 先行），产出符号表。
5. UI：引用 chip 展示、可移除、超限提示。

**验收**
- 引用 5 个大文件触发压缩后，请求成功且模型仍能正确回答文件相关问题（人工抽查 10 例）。
- token 计数与官方 tokenizer 对比误差 < 3%。

### M4 Agent 闭环（**已完成**，实测见 [`10-M4-验收报告.md`](./10-M4-验收报告.md)；原估 5–6 天）

**任务**
1. `crates/agent`：循环调度、消息拼装、工具注册表。
2. 6 个核心工具实现（read/list/grep/write/edit/create），含路径安全与截断。
3. `run_command`：独立进程组、超时杀进程树、stdout/stderr 流式回传。
4. diff 引擎：生成 unified diff、UI diff 视图、接受/拒绝/逐块应用。
5. 权限：规则表 + 裁决点 + 审批 UI（四种动作）。
6. 工具调用卡片 UI：参数、状态、耗时、输出展开。

**验收**
- **端到端基线任务**（脚本化）：
  1. "解释 src/main.ts 的入口流程" → 一次 read 后正确回答；
  2. "给所有 fetch 加 5s 超时" → edit + diff 应用，`git diff` 结果符合预期；
  3. "跑 pnpm test，红了就修到绿" → 命令执行 + 迭代修复；
  4. "把 utils 目录重命名成 helpers 并修复所有 import" → grep + edit 多处 + 命令验证。
- `edit_file` 抗幻觉测试：构造 20 个"非唯一匹配"用例，自动重试成功率 ≥ 90%。

> M4 验收实测（2026-10-21，`pnpm e2e:m4`，真实模型 `deepseek-v4-pro`）：上述 4 条基线任务 **4/4 通过**；20 个非唯一匹配用例 **20/20 通过（100%，≥90% 达标）**，其中 19 例首轮撞「无法唯一匹配」后补足上下文全部重试成功。逐条数据、口径与限制见 [`10-M4-验收报告.md`](./10-M4-验收报告.md) 第七节（沙箱内以 `node test.mjs` 等价替代 `pnpm test`）。
- 安全测试：构造 `..\..\Windows\System32` 路径与 `format C:` 命令，必须被拒绝。

### M5 持久化与治理（**已完成**，实测见 [`11-M5-验收报告.md`](./11-M5-验收报告.md)）

**任务**（四条均已落地）
1. `crates/store`：sqlx 迁移、会话/消息/审计/权限表。
2. 会话 UI：历史列表、搜索、重命名、删除、导出 Markdown/JSON。
