# 24 · 插件 UI 贡献点设计（声明式视图 + 外部视口）

> 状态：**设计定稿，待实现**（2026-10-28）
> 关联：[14 插件系统设计](./14-插件系统设计.md) · [02 §8 安全模型](./02-系统架构设计.md) · [03 内核接口协议规范](./03-内核接口协议规范.md)
> 首个消费者：`asset3d` 插件（3D 资产检视器）
> 落点依据：本文所有 `文件:行` 均基于当前仓库逐行核对（2026-10-28），调研记录不入库，以正文为准。

---

## 1. 定位

14 号文档的 §1.1 把「UI 贡献点」列在 v1 不做，ADR-11 给的理由是"要打通 Core→Main→Renderer 三段事件链，Renderer 是 sandbox 的，插件 UI 一旦能执行就是新的攻击面"。

本文要解决的是：**在不放开 Renderer 沙箱、不引入 webview/iframe、不放开 `script-src 'self'` 的前提下，让插件能往 IDE 里放自己的界面**。

答案是把"界面"降级为**纯数据**：插件只描述"要显示什么"，宿主用内置控件解释这份描述。插件代码永远不进渲染进程。代价是复杂交互做不了——这类需求（3D 视口）交给**插件自己的独立可执行文件**，IDE 只负责唤起、定位、并把离散动作送过去。

### 1.1 范围

| 本期做 | 本期不做 |
|---|---|
| `manifest.views[]` 声明与三段校验 | 插件提供 HTML / JS / CSS 资源包 |
| `aiide.view/1` 声明式视图描述与 12 类内置控件 | `webview` / `iframe` / 自定义协议承载插件页面 |
| `plugin.status` 下发视图摘要、`plugin:view` 刷新事件 | 插件自定义主题、状态栏、语法高亮 |
| `external` 外部视口程序声明与受控 spawn | 插件间通信、插件市场 |
| 命名管道会话协议 `asset3d.session/1` | 视口窗口嵌入 IDE（Win32 停靠为可选优化） |
| 视图按钮 → `plugin.command` 的审批闭环（含 `ApprovalCard` 抽取） | 视图中承载连续交互（拖拽 / 高频滑块） |
| 视口 `--standalone` 参数（不依赖 IDE 直接开图） | 视口缩略图截图（`screenshot` 只留协议位，本期不实现） |

### 1.2 一句话结论

> 插件 UI = **一纸声明（manifest）+ 一棵描述树（工具返回的 JSON）**，由宿主内置控件渲染；需要真渲染的地方，插件另起**独立可执行文件**，通过**命名管道**与 IDE 通信，IDE 只发离散命令。

## 2. 继承的不变量

| 不变量 | 依据 | 对本设计的约束 |
|---|---|---|
| 能力清单不可虚报 | `dispatch.rs:189-201` 穷举 match、`methods.rs` 的 `IMPLEMENTED` | **不新增 `plugin.*` 方法**；视图摘要搭 `plugin.status` 的车，视图内容走 `plugin.call` |
| `plugin.*` 才需进方法表 + `policy.ts` 白名单 | 14 号 §5.3 | 不新增方法就没有新的 policy 行要放行 |
| 插件输出不可信 | 14 号 §2 第 4 条 | 视图描述是**纯数据**，宿主不 `eval`、不拼 DOM 字符串、不解析为控制流 |
| CSP 是硬红线 | `renderer/index.html:8` 的 `script-src 'self'` | 不放开脚本源；不启用 `webviewTag`；不加 `frame-src` |
| 副作用集中 Core | 02 §8 | 写盘仍走 `host/fs.write` + `plugin_approver`；视口程序只读 |
| `pluginApi` major 严格匹配 | ADR-13 | `views[]` 是**新增可选字段**，minor 升级，旧插件不受影响 |

## 3. 决策记录（续 14 号 ADR-13）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-14 | 插件 UI 是**声明式 JSON**，插件不携带可执行前端资源 | ①插件发 HTML/JS 由 webview 承载 ②插件编译 WASM 提供渲染器 | ①要开 `webviewTag` + 收窄 `script-src`，ADR-11 的安全立论直接失效，且 CSP 一旦放开无法按插件回退；②WASM 可行但首版成本高、调试差，留作未来升级路径。声明式的攻击面仅为"UI 显示异常"，不可能导向代码执行 |
| ADR-15 | 视图**声明**随 `plugin.status` 下发，视图**内容**由 `entry` 工具按需返回 | ①把完整视图塞进 manifest ②新增 `plugin.view` 方法 | ①manifest 是安装期静态文件，塞数据等于绕开插件进程与闸门，且 `status` 会随插件数量线性膨胀；②新增方法要同步四处（methods/policy/bindings/契约测试），违背"能不加方法就不加" |
| ADR-16 | 3D 渲染**不进 Renderer**，由插件提供**外部视口可执行文件** | 宿主内置 three.js + AIR 加载器 | 解析器与 wgpu 渲染已在 Rust 侧，TS 重写等于两套 AIR 语义并行漂移；且直读文件不受 1 MiB 帧上限、200 次配额、base64 膨胀约束 |
| ADR-17 | IDE ↔ 视口走**命名管道 + 行分隔 JSON** | ①复用 stdio（已被 RPC 帧占用）②本地 TCP（端口/防火墙，同 ADR-2 否决理由）③文件轮询（延迟与清理问题） | 管道天然单机、可按 SID 设 ACL、无端口冲突；行分隔便于人工调试 |
| ADR-18 | 视口内的高频交互（相机、播放、逐帧）**不回流 IDE**；IDE 面板只读 | 让 IDE 面板做播放控制 | `plugin.command` 每次过 `risk` 与审批链，承载 60 Hz 连续值属误用；绕开审批就要新开旁路通道，得不偿失 |

## 4. 能力层：声明式视图

### 4.1 manifest 增 `views[]`

```json
{
  "id": "asset3d",
  "pluginApi": { "major": 1, "minor": 1 },
  "views": [
    {
      "id": "main",
      "title": "3D 资产",
      "location": "pluginPanel.detail",
      "entry": "view.render",
      "refresh": ["workspace.changed", "file.saved"],
      "external": {
        "program": "asset3d-gui.exe",
        "protocol": "asset3d.session/1"
      }
    }
  ]
}
```

字段约束：

| 字段 | 必填 | 约束 | 违反时 |
|---|---|---|---|
| `id` | 是 | `^[a-z][a-z0-9_-]{0,31}$`，包内唯一（独立 `is_valid_view_id`，`manifest.rs:1419`；**不复用** `is_valid_id`——后者形状为 `^[a-z0-9][a-z0-9-]{1,63}$`，不允许 `_` 且最短 2 字符） | 6107 |
| `title` | 是 | 1–48 字符，禁控制字符 | 6107 |
| `location` | 是 | 首版仅 `pluginPanel.detail` | 6107 |
| `entry` | 是 | 必须出现在本插件 `tools[]` 中，且 `risk == "read"` | 6108（未声明）/ 6107（受邀写） |
| `refresh` | 否 | 取自固定枚举：`workspace.changed` / `file.saved` / `session.ended` | 6107 |
| `external.program` | 否 | 插件包内相对路径，不含 `..`，扩展名 `.exe`，安装时校验真实存在 | 1002（越界）/ 6107 |
| `external.protocol` | 否 | 宿主白名单：当前仅 `asset3d.session/1` | 6107 |

对外 DTO 为 `PluginViewSummary`（`dto.rs:3549`）：`refresh` 恒定存在（缺省 `[]`），`external` 缺省时整个键不出现，前端可凭 `external` 有无分派到「描述树」或「外部视口」两条渲染路径。

三个刻意的取舍：

1. **`entry` 必须是 `read` 工具**。视图加载不得触发写盘或审批，否则用户点开一个面板就要点一次"允许"。
2. **`location` 只开一个值**。渲染端侧栏是 `ActivityView` 固定枚举（`store.ts:29-37`），动态视图必须挂在 `PluginPanel` 详情区做二级 tab，否则每个插件都要改外壳枚举。
3. **`Manifest` 保持不加 `deny_unknown_fields`**（`manifest.rs:111`）。这是双向兼容的唯一保障：旧宿主读新清单会静默忽略 `views`，只是不显示。

### 4.2 视图描述 `aiide.view/1`

`entry` 工具返回的工具结果中，`ui` 字段承载描述树：

```json
{
  "schema": "aiide.view/1",
  "rev": 12,
  "root": {
    "type": "column",
    "children": [
      { "type": "group", "title": "资产", "children": [
        { "type": "stat", "label": "网格", "value": "3" },
        { "type": "stat", "label": "三角面", "value": "12,480" }
      ]},
      { "type": "list", "label": "动画",
        "items": [ { "key": "Idle", "label": "Idle · 2.00s" },
                   { "key": "Run",  "label": "Run · 0.80s" } ] },
      { "type": "row", "children": [
        { "type": "button", "label": "打开视口",
          "action": { "command": "openViewport", "args": { "path": "art/chair.fbx" } } },
        { "type": "button", "label": "导出 AIR",
          "action": { "command": "exportAsset", "args": { "path": "art/chair.fbx" } } }
      ]}
    ]
  }
}
```

节点结构统一为：

```
Node = { type, id?, label?, title?, value?, items?, children?, props?, action? }
```

### 4.3 控件白名单与硬上限

| 类别 | 控件 | 备注 |
|---|---|---|
| 布局 | `row` `column` `group` `tabs` | `tabs` 的 `items[].children` 为每页内容 |
| 展示 | `text` `stat` `table` `list` `tree` `progress` | `table` 支持 `columns[]` / `rows[][]`，只读 |
| 输入 | `toggle` `slider` `select` `color` | 值变更只能产出 `command`，不直连插件 |
| 动作 | `button` | `action.command` 必须命中 manifest `commands[].id` |

硬上限（宿主侧校验，超出即截断并计入诊断，不报错中断）：

| 项 | 上限 | 处理 |
|---|---|---|
| 节点总数 | 2000 | 截断，末尾追加一行"内容过多已截断" |
| 树深度 | 16 | 该子树渲染为占位 |
| 序列化体积 | 256 KiB | 整棵树拒渲染，展示错误态 |
| 单字符串 | 4 KiB | 截断 |
| `list` / `table` 行数 | 500 | 截断 + 提示"仅显示前 500 条" |

未知 `type`：渲染为灰底占位块并记一条渲染诊断，**不抛异常、不整块白屏**。这条是为未来控件扩展留的容错。

### 4.4 安全校验（宿主侧，渲染前）

1. `action.command` 不在本插件 `commands[]` → 按钮渲染为禁用态并写审计事件 `view.action_rejected`。
2. 任何字段出现 `http://` / `https://` / `data:` / `javascript:` / `file://` 字符串 → 该字段作纯文本转义显示，不生成可点击元素（白名单里没有 `link` 控件，这是故意的）。
3. 所有字符串经 React 文本节点渲染，禁止 `dangerouslySetInnerHTML`（沿用 `PluginPanel.tsx:592` 既有工具/命令区块的写法）。
4. `external.program` 只在用户点"打开视口"时使用，且经主进程校验后才 `spawn`。

### 4.5 通道与事件

| 用途 | 走法 | 是否新增 |
|---|---|---|
| 拉取视图描述 | `plugin.call { id, method: entry, params }` | 否，复用现有网关（`plugin_api.rs:1380`，六步定序 + 能力/声明/配额全过） |
| 触发视图动作 | `plugin.command { id, command, args }` | 否，复用现有网关（`plugin_api.rs:1848`，走 `risk` + 审批） |
| 插件主动要求刷新 | 新事件 `plugin:view`，载荷 `{ pluginId, viewId, rev }` | 新增第 4 条遥测通道 |
| 大块字节 | 本版不需要（视口自己读盘） | — |

`plugin:view` 刻意**不带数据体**：事件只负责"去重拉"，数据永远走 `plugin.call`，否则等于给插件开了一条绕过闸门的数据通道。

事件四处联动（落点已在调研中核对）：

- `crates/plugin/src/events.rs:39` 后加 `PLUGIN_VIEW`
- `crates/core/src/plugin_host.rs:561` 旁加 `announce_shell_view`（仿 `announce_shell_state`）
- `apps/desktop/src/main/index.ts:153-158`、`:193-196` 加通道映射
- `apps/desktop/src/preload/index.ts:146` 后加 `onPluginView`
- `apps/desktop/src/renderer/plugin-activity-store.ts:278` 旁加订阅

## 5. 外部视口（X4）

### 5.1 进程拓扑

```
┌──────────────┐  白名单 IPC  ┌──────────────┐   stdio JSON-RPC  ┌───────────────────────┐
│  Renderer    │ ───────────▶ │    Main      │ ────────────────▶ │  Core                 │
│  sandbox     │              │  策略裁决     │                   │  PluginHost(asset3d)  │
│              │              │              │                   │   └ plugin/*.rs       │
│  声明式视图   │              │  spawn 校验   │                   └───────────────────────┘
└──────────────┘              └──────┬───────┘
                                     │ spawn(exePath, argv[])  ← 无 shell 拼接
                                     ▼
                            ┌──────────────────────┐
                            │ asset3d-gui.exe      │  原生窗口 winit + wgpu
                            │  视口 / 时间轴 / 骨骼 │
                            └──────────┬───────────┘
                                       │ 命名管道（行分隔 JSON）
                                       ▼
                        \\.\pipe\asset3d.viewport.<sid>
```

三条硬边界：

1. **GUI 不能进插件宿主进程**。`asset3d.exe` 是 stdio 帧泵（`loader.rs` 按行读帧），winit 事件循环会抢线程；且插件崩溃自动重启（`host.rs:536`，同次上限 3）会连带杀掉窗口。
2. **GUI 不能接管 stdio**，否则与 RPC 帧冲突，直接判 6106。
3. **GUI 独立可单实例运行**，不依赖 IDE 存在。

### 5.2 会话协议 `asset3d.session/1`

行分隔 JSON，每行一条，`{"v":1,"op":"...","seq":N,...}`。未知 `op` 与未知字段一律忽略（向前兼容），`seq` 用于请求/回执配对，`seq=0` 表示单向通知。

| 方向 | op | 载荷 | 语义 |
|---|---|---|---|
| IDE→视口 | `open` | `{path, animation?, camera?, play?}` | 打开资产；`path` 为工作区相对路径，由插件宿主校验后转发 |
| | `close` | `{}` | 关闭当前资产（不退出进程） |
| | `focus` | `{}` | 置前并抢焦点 |
| | `screenshot` | `{path, width?}` | **本期预留，不实现**：op 与载荷在协议中占位，视口收到即回 `error{code:"unsupported"}`；后续版本再评估（要多处理 DPI 缩放与写入时机） |
| | `ping` | `{}` | 心跳，5 s 间隔，3 次无 pong 视为失联 |
| 视口→IDE | `ready` | `{version, capabilities:["static","skin","anim"]}` | 握手完成，能力自述 |
| | `state` | `{path, animation, time, playing, camera}` | 状态变更（打开 / 切换动画 / 播放暂停），非逐帧 |
| | `selection` | `{mesh, node}` | 用户在视口内点选 |
| | `error` | `{code, message}` | `parse_failed` / `validate_failed` / `file_missing` / `unsupported` |
| | `pong` | `{seq}` | 心跳回执 |

刻意不做的事：**不传几何数据**。视口自己读盘解析（无 1 MiB 帧上限、无 200 次配额、无 base64 膨胀）；`state` 只在离散事件上发，不逐帧推送——逐帧回流会让 IDE 面板变成一块 60 Hz 刷新的日志板。

### 5.3 生命周期与单实例

| 场景 | 行为 |
|---|---|
| IDE 点"打开视口"，管道不存在 | 主进程 `spawn(program, ["--pipe", pipeName])`，等待 `ready`（超时 10 s → 报错并提示查看插件日志） |
| 管道已存在 | 直接连接发 `open`，不重复 spawn |
| 用户手动双击 `asset3d-gui.exe` | 先抢互斥体 `Local\asset3d.viewport`；抢到则创建管道并监听，抢不到则按默认管道名连接已有实例并转发参数后自身退出 |
| 命令行 `asset3d-gui.exe --standalone <asset>` | 不连管道、不抢视口互斥体的"看图模式"（既有无 IDE 场景一步到位）；抢 `Local\asset3d.viewport.standalone.<abs-path-hash>` 保证同一资产不重复开窗 |
| IDE 退出 | 不杀视口进程（用户可能正在看），仅断开管道 |
| 视口退出 | 管道断开，插件下一次 `openViewport` 时重新 spawn |
| 视口崩溃 | 无自动重启（与插件宿主不同：窗口崩溃是用户可见事件，静默重启会让用户困惑），IDE 面板显示"视口已关闭"，按钮变回"打开视口" |

互斥体用 `Local\` 前缀（会话级），允许多用户会话各开一个，避免全局锁。

#### 5.3.1 `--standalone` 参数

视口进程启动形态有三种，靠 argv 区分，解析在 `main.rs` 里最前面完成（早于 winit 初始化，失败只走 stderr + 退出码）：

| argv | 形态 | 行为 |
|---|---|---|
| `--pipe <name>` | IDE 托管 | 连接指定管道，监听指令，IDE 断开后进程继续存活 |
| `--standalone <asset>`（可带 `--animation` / `--play`） | 独立看图 | 不创建也不连接管道，启动即 `open`，窗口标题带资产名 |
| 无参数 | 手动双击 | 按 §5.3 的互斥体规则决定"创建管道监听"还是"连接已有实例" |

约束：

1. `--standalone` 与 `--pipe` 互斥，同时给出按参数错误退出（码 2），不做"两个都试"的兜底。
2. 路径先做 `canonicalize`，不存在或越出允许根（工作区或用户显式授权目录）→ 退出码 3，stderr 一行原因；不弹对话框（standalone 场景无人值守，可能是脚本拉起）。
3. 该模式下视口**不写**会话状态文件、不落 `recent.json`，避免 IDE 面板读到"IDE 没打开过"的记录。
4. Windows 上以 `windows-subsystem=windows` 构建时无控制台，退出码只能通过进程退出观察到；文档与测试以退出码为准。

好处是这条模式顺带成为 M-UI-3/M-UI-4 的调试入口：不必起 IDE 就能验渲染与动画，省掉一整轮"改代码→重启 Electron→连管道"的循环。

### 5.4 spawn 安全

主进程 `spawn` 前逐项校验，任一失败即拒绝并返回错误码：

1. `program` 解析为插件安装目录下的绝对路径，规范化后仍在该目录内（防 `..` 与符号链接逃逸）。
2. 扩展名为 `.exe`。
3. 文件存在且可执行（`fs.access`）。
4. 参数以数组传递，**不经 shell**，不拼接字符串（杜绝命令注入）。
5. 子进程 `stdio` 设为 `ignore`，不继承父进程句柄；环境变量只透传最小集合（`PATH` / `TEMP` / `USERPROFILE`），不传 IDE 的密钥类变量。

视口进程侧不监听任何网络端口，管道 ACL 限定当前用户 SID。

### 5.5 交互边界（ADR-18 的落地）

| 交互 | 位置 | 理由 |
|---|---|---|
| 轨道相机、缩放、平移 | 视口内 | 连续值，回 IDE 无意义 |
| 播放 / 暂停 / 逐帧 / 倍速 | 视口内 | 高频 |
| 动画切换 | 视口内（列表 + 下拉） | 高频 |
| 骨骼线框 / AABB / 网格拾取 | 视口内 | 需要即时反馈 |
| 资产统计、材质表、动画清单 | IDE 面板（只读） | 一次性数据，无需交互 |
| 打开视口、导出 AIR / 加载器 | IDE 面板按钮 → `plugin.command` | 需要审批留痕 |

IDE 面板不知道"当前播到第几帧"，这是刻意接受的代价：实时同步要新增一条高频通道，而它带来的价值（面板上看到一个数字在跳）不足以抵消复杂度。
