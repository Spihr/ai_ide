# AI IDE 需求规格说明（SRS）

> 文档版本：v0.1（待审阅）
> 状态：草案 · 需求基线；实现进度见 [00-README.md](./00-README.md) 的「实现状态」章节（M0–M4 已实现并通过实测验收，M5 起未开工）

---

## 1. 项目定位

构建一款**本地优先、模型可插拔的 AI 原生代码编辑器**（AI-Native IDE）。核心主张：

1. **模型自由**：通过配置 API（Base URL / API Key / Model ID）接入任意 OpenAI 兼容或原生协议的大模型，不绑定单一厂商。
2. **Agent 优先**：AI 不止于聊天，而是能读写文件、执行命令、观察结果、多步迭代直至任务完成。
3. **本地优先**：代码索引、会话、密钥全部落在本机；除调用模型 API 外无强制联网依赖。
4. **工程可控**：Rust 内核承担索引、解析、终端、进程、网络等重负载；Electron + React 承担 UI 与交互。

## 2. 目标用户与核心场景

| 用户画像 | 核心诉求 | 典型场景 |
|---|---|---|
| 独立开发者 / 学生 | 少写样板、快速读懂陌生仓库 | "解释这个模块"、"给这个函数加错误处理" |
| 多模型使用者 | 不同任务用不同模型（便宜模型跑杂活、强模型做架构） | 会话内切换模型，按任务分配预算 |
| 本地 / 私有部署用户 | 数据不出内网 | 接入 Ollama / vLLM / 自建网关 |
| 重度终端用户 | AI 直接跑命令看结果 | "跑测试，红了就修到绿" |

## 3. 功能需求

## 4. 非功能需求

| 类别 | 编号 | 要求 |
|---|---|---|
| 性能 | NFR-1.1 | 冷启动到可交互 < 3s（不含内核预热） |
| 性能 | NFR-1.2 | 10 万文件工作区全量索引 < 30s，增量索引 < 500ms 感知延迟 |
| 性能 | NFR-1.3 | 首 token 渲染延迟 = 网络往返 + < 100ms 本地开销 |
| 性能 | NFR-1.4 | 编辑 1 万行文件时输入延迟 < 16ms（60fps） |
| 性能 | NFR-1.5 | 空闲内存占用 < 600MB（Electron 壳 + 内核 + 渲染） |
| 安全 | NFR-2.1 | 所有文件路径经规范化 + 工作区边界校验，禁止 `..` 越界 |
| 安全 | NFR-2.2 | 命令执行黑名单（`format` / `rm -rf /` / 注册表破坏类）+ 用户确认 |
| 安全 | NFR-2.3 | API Key 不以明文落盘、不出现在日志与遥测中 |
| 安全 | NFR-2.4 | Agent 文件写入不触及系统敏感目录（`C:\Windows`、`Program Files`、`.ssh`、`.git` 内部等） |
| 安全 | NFR-2.5 | 渲染进程启用 `contextIsolation`、`sandbox`，禁用 `nodeIntegration` |
| 可靠性 | NFR-3.1 | 内核进程崩溃自动重启并恢复会话状态，UI 不白屏 |
| 可靠性 | NFR-3.2 | 未保存内容断电级保护（草稿本地暂存） |
| 兼容 | NFR-4.1 | Windows 10/11 优先；架构预留 macOS / Linux |
| 兼容 | NFR-4.2 | 支持 Node 20+ / Rust 1.79+ 工具链 |
| 可维护 | NFR-5.1 | 内核与 UI 通过稳定协议解耦，可独立测试与替换 |
| 可维护 | NFR-5.2 | 关键路径单元测试覆盖率 ≥ 70%，协议层 100% 契约测试 |
| 可观测 | NFR-6.1 | 结构化日志（JSONL），分模块可调级别，日志脱敏 |
| 国际化 | NFR-7.1 | UI 中英双语（默认跟随系统） |

## 5. 竞品对标

| 能力 | Cursor | Claude Code | Marvis（本机助手） | 本项目目标 |
|---|---|---|---|---|
| 形态 | 独立 IDE（VS Code Fork） | CLI + IDE 插件 | 桌面 AI 助手 + 系统级操作 | 独立桌面 IDE |
| 模型接入 | 官方托管为主，可配 Key | Anthropic 为主 | 平台托管 | **完全 BYOK，多协议多 Provider** |
| Agent 工具循环 | 有（Composer / Agent） | 有（强） | 有（含系统/App 操作） | P0 落地（文件 + 命令） |
| 上下文引用 | `@` 系列 | 自动 + 手动 | 系统级上下文 | P0 落地 `@` 系列 |
| diff 预览与应用 | 有 | 有 | 有 | P0 落地 |
| MCP | 有 | 有 | 有 | P1 落地 |
| 终端集成 | 有 | 强 | 有 | P1 落地 |
| 本地模型 | 有限 | 无 | 无 | P1 落地（Ollama 等） |

**差异化定位**：做一个"模型中立 + 本地优先 + 内核可替换"的开放形态 IDE——用户自带任意 API，内核用 Rust 保证索引与进程管理的性能与稳定性。

## 6. MVP 边界

**范围内（MVP = M0–M5）**
- 单窗口 / 单工作区、文件树、Monaco 多标签编辑与保存
- 文件搜索（name + content）
- Provider 配置中心 + OpenAI 兼容协议 + 流式对话
- `@文件 / @文件夹 / @选区 / @打开文件` 上下文引用
- Agent 模式：`read_file / write_file / edit_file / list_dir / grep / run_command` + 权限确认 + diff 预览
- 会话本地持久化（SQLite）

**范围外（MVP 不做，后续里程碑补）**
- 内置终端、Git UI、LSP 深度集成（P1）
- MCP、Tab 补全、检查点、插件系统（P1/P2）
- 团队协作、云同步、账号体系
- 移动端

## 7. 术语表

| 术语 | 含义 |
|---|---|
| Provider | 一个模型服务端点配置（Base URL + Key + 协议类型） |
| Model | Provider 下的具体模型条目（Model ID + 能力标注） |
| Agent 循环 | 模型输出工具调用 → 本地执行 → 结果回灌 → 再次推理的迭代过程 |
| Tool Call | 模型请求执行的本地动作，遵循 JSON Schema 声明 |
| 上下文引用 | 显式把文件/片段/外部内容注入当轮 prompt 的机制 |
| Checkpoint | 工具调用前的文件系统快照，用于回滚 |
| FIM | Fill-in-the-Middle，代码补全范式 |
| MCP | Model Context Protocol，模型上下文协议，用于接入外部工具服务 |
