## 一、静态预检结论（本机已完成，2026-10-24）

在出包机上直接对安装包与包内二进制做静态检查，得到三条**会直接影响真机验收结果**的事实：

| # | 检查 | 方法 | 结论 | 对验收的影响 |
|---|---|---|---|---|
| 1 | 内核依赖 VC++ 运行库 | `pefile` 解析 `resources/core/ai-ide-core.exe` 导入表 | **修复前：是**（22 个导入 DLL，含 `VCRUNTIME140.dll`）；**修复后：否**（13 个导入 DLL，无任何 CRT DLL，见 §1.2） | 修复前 S4「运行库缺失」必然失败；按方案 A 静态 CRT 修复后该阻塞项消除 |
| 2 | 安装包/外壳未签名 | `Get-AuthenticodeSignature` | `NotSigned`（内层 `AI IDE.exe` 同样） | S5 SmartScreen 预期弹「Windows 已保护你的电脑」，需「更多信息 → 仍要运行」 |
| 3 | 安装范围 | `electron-builder.yml`：`perMachine: false` | 用户级安装 → `%LOCALAPPDATA%\Programs\AI IDE`，注册表在 `HKCU\...\Uninstall`，静默安装**不需管理员** | S1 不应弹 UAC；若弹，说明被回退到 perMachine |
| 4 | 包内是否自带运行库 | 列 `win-unpacked` 根目录 DLL | **没有** `vcruntime140*.dll`，也没捆 `VC_redist.x64.exe` | 与第 1 条叠加 → 确认缺库即挂 |
| 5 | 卸载是否保留用户数据 | `deleteAppDataOnUninstall: false` | 卸载保留 `%APPDATA%\AI IDE`（会话库/日志/配置） | S3 断言「卸载后用户数据仍在」为**预期行为**，不是残留 bug |

### 1.1 阻塞项 R1：运行库缺失场景必然失败（已按方案 A 修复，见 §1.2）

证据链：`core/Cargo.toml` 未开静态 CRT（默认动态链接 MSVC CRT）→ 二进制导入表含 `VCRUNTIME140.dll` → 包内与安装包均未附带该 DLL 与 VC redist → 宿主未装 VC++ 2015-2022 x64 运行库时，内核进程无法启动。

三条修复路线，建议按顺序评估：

| 方案 | 做法 | 优点 | 代价/风险 | 评价 |
|---|---|---|---|---|
| **A. 静态 CRT（推荐）** | 给内核构建加 `RUSTFLAGS=-C target-feature=+crt-static`（或 `.cargo/config.toml` 配 `target.x86_64-pc-windows-msvc.rustflags`） | 彻底消掉 `VCRUNTIME140.dll` 依赖，安装包不变大，无需管理员装 redist | 需全量重编内核 + 重打包 + 重跑 `e2e:m8`；需确认 `rusqlite(bundled)` / `rustls(aws-lc-rs 或 ring)` / `portable-pty` 支持静态 CRT | 一次性根治，装机零前置条件 |
| **B. 安装包捆绑 VC_redist** | `electron-builder.yml` 的 `nsis.include` 加自定义脚本，安装前静默执行 `VC_redist.x64.exe /install /quiet` | 官方路线 | 体积 +25MB；`perMachine:false` 的用户级安装装 redist **需要管理员**，会打断免 UAC 体验；失败需回滚处理 | 与当前 perUser 设计冲突 |
| **C. app-local 分发 DLL** | 把 `vcruntime140.dll` + `vcruntime140_1.dll` 放进 `resources/core/`（`extraResources`） | 改动最小，无需重编内核、无需管理员 | 依赖微软 redist 的 app-local 分发许可；DLL 与工具链版本需绑定记录；双击内核所在目录时需保证同目录可见 | 快速止血，长期不如 A 干净 |

> 在 R1 修复前，S4 场景可先按「预期失败」记录执行结果（脚本会把缺失的 `vcruntime140.dll` 标为 WARN，并把内核握手标为 FAIL），以此作为修复前基线证据。

### 1.2 R1 修复记录：方案 A（静态 CRT）已落地

**决定**：采用方案 A，内核改为静态链接 MSVC CRT。理由：售前无需管理员装 redist、包体不增大、一次性根治；本机验证 `rusqlite(bundled)` / `rustls` / `portable-pty` 均能在静态 CRT 下正常编译运行。

**改动**：`.cargo/config.toml` 新增

```toml
[target.x86_64-pc-windows-msvc]
rustflags = ["-C", "target-feature=+crt-static"]
```

只作用于 Windows MSVC 目标，不影响 Linux/macOS 构建，也不改动全局环境。

**复验结果（2026-10-24，出包机）**：

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 内核导入 DLL 数量 | 22 | **13** |
| `VCRUNTIME140.dll` / `MSVCP140.dll` | 依赖 | **无** |
| `api-ms-win-crt-*`（UCRT 转发） | 依赖 | **无**（UCRT 已静态并入） |
| 内核体积 | 19.1 MB | 19.1 MB（无明显变化） |
| `win-unpacked` 内 9 个 exe/dll 的 CRT 依赖扫描 | 内核命中 | **0 命中** |
| `pnpm dist`（含 `verify:package --installer`） | PASS 11 项 | **PASS 11 项** |
| `pnpm e2e:m8` | 13/13 | **13/13** |

静态化后内核仅剩系统 DLL：`KERNEL32 / ADVAPI32 / ole32 / oleaut32 / shell32 / userenv / ws2_32 / bcrypt / bcryptprimitives / ntdll` 等，Win10 1809+ 全部自带。

> 注意：`target/debug/ai-ide-core.exe` 仍是旧构建（动态 CRT），仅用于开发调试，不参与打包；打包链路只取 `target/release`。

**验收口径变化**：S4 从「预期 FAIL 基线」转为「**预期 PASS**」——干净无 VC++ 运行库的机器上，内核应能直接启动并完成握手。

## 二、VM 准备（一次性）

1. **要一台干净机**：全新 Windows 11（或 Windows 10 21H2+）虚拟机，**不要**装 Visual Studio / VC++ 运行库 / 任何 Python、Node 环境，避免掩盖缺失依赖。
2. **建快照**：装包前打一个快照 `clean-baseline`，每个场景跑完回滚，保证「首次安装」是真首次。
3. **把安装包传进去**：
   - 走共享文件夹 / 网络路径：`\\vmware-host\Shared Folders\...`、Hyper-V 增强会话复制粘贴；
   - **注意 MOTW**：浏览器下载或 `\\` 网络路径拷入会带 Zone.Identifier，才会触发 SmartScreen；USB/ISO 挂载拷入通常不带，S5 需专门用带 MOTW 的副本验。
4. **测「运行库缺失」用第二台快照**：确保 `C:\Windows\System32\vcruntime140.dll` 不存在（脚本阶段 0 会打印）。
5. 建议配置：2 vCPU / 4GB 内存 / 60GB 磁盘；分辨率 1920×1080，另备一个 2560×1440 副屏（S6 多显示器）。

## 三、执行方式

把安装包与脚本一起放进 VM，然后：

```powershell
# 全链路（安装 → 首启 → 卸载）
powershell -ExecutionPolicy Bypass -File .\verify-nsis-install.ps1 `
  -InstallerPath "$env:USERPROFILE\Downloads\AI-IDE-0.1.0-win-x64.exe"

# 覆盖升级（先装旧版，再装新版，验用户数据保留）
powershell -ExecutionPolicy Bypass -File .\verify-nsis-install.ps1 `
  -InstallerPath "$env:USERPROFILE\Downloads\AI-IDE-0.1.0-win-x64.exe" `
  -PreviousInstallerPath "$env:USERPROFILE\Downloads\AI-IDE-0.0.9-win-x64.exe"

# 只验安装，保留现场手工点开看看
powershell -ExecutionPolicy Bypass -File .\verify-nsis-install.ps1 -InstallerPath ... -SkipUninstall
```

报告落在桌面 `ai-ide-m8-acceptance\m8-nsis-acceptance-<时间戳>.md|.json`，退出码 `0` 表示 FAIL=0。

脚本只做这几件事：读注册表卸载项、启动/结束 `AI IDE` 与 `ai-ide-core` 进程、执行安装包与卸载器的 `/S` 静默参数、写报告。它不改系统策略、不删 `%APPDATA%\AI IDE`。
